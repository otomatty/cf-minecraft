# M2: オリジナルの地形生成の土台

地形生成は自作する。本家と同じ地形、ブロック一覧、乱数列の再現は目標にしない。
勾配ノイズ、オクターブ、密度関数などの一般的な技法を使い、パラメータ、分類、データは独自に設計する。
逆コンパイルしたコードやゲームのデータは使用しない。

`DebugHills` と `Flat` の出力は維持し、新規ワールドの既定は Terrain にする。`Terrain` (id 2) は独立した新しい地形生成で、バイオームはまだ接続しない。

## レジストリ

`data/registry/blocks.toml` と `biomes.toml` が入力。
`crates/world/build.rs` が `serde` (derive) と `toml` 0.8 で読み込み、検証して
`OUT_DIR` に Rust の静的な表を生成する。入力の変更は `cargo:rerun-if-changed` で検出する。
生成物はコミットしない。依存は build-dependencies だけで、`world` の実行時依存は増えない。

### ブロックの追加

`blocks.toml` の末尾に `[[blocks]]` を追加する。例えば現在の40状態の後なら次の4行で追加できる。

```toml
[[blocks]]
name = "clay_tile"
id = 40
texture = "stone"
```

これで `CLAY_TILE`、状態 ID、`COUNT`、ブロック一覧、文字列への変換と解析が生成される。
新しいテクスチャ名を使う場合は、ファイル先頭の `textures` 配列の末尾にその名前を追加し、
`texture = "clay_tile"` のように参照する。配列順が atlas の層番号になるため、既存の宣言順は変えない。
テクスチャ名はクライアントにも渡る。絵柄が未実装の名前には既存の紫黒チェックが表示される。
新しい画像が必要なら、公式パックの画像への対応付けを追加し、仮パックにも画像を用意する。[対応付けと仮パックの追加手順](texture-packs.md#開発と検証)

`name` は小文字の snake_case で、大文字にした名前が公開 Rust 定数になる。
`id` はブロックの最初の状態 ID。前のブロックの直後に連続させ、既存 ID を動かさない。
衝突・欠番はビルドエラーになり、既存 ID・atlas 順の変更は互換性テストでも検出する。
`legacy_count` は従来形式の14状態の境界であり、追加時にも変更しない。

### 面と tint の省略形

`texture` は6面共通のテクスチャ。`top`、`bottom`、`side` (水平4面)、
`north`、`south`、`west`、`east` で必要な面だけ上書きできる。
優先順位は個別の面、`side`、`texture` の順。上下には `side` を適用しない。
`top` / `bottom` は `up` / `down` とも書ける。
すべての面にテクスチャが解決できなければビルドエラーになる。

```toml
[[blocks]]
name = "grass_block"
id = 2
top = "grass_block_top"
bottom = "dirt"
side = "grass_block_side"
tint = ["top", "side"]
```

`tint` は省略すると全6面 false。`tint = true` で全面、`tint = ["top", "north"]` のように
面名の配列で指定した面だけを着色できる。`side` は水平4面、`up` / `down` も使用可能。
草・葉・水の既存の着色方法は維持する。

### モデル、描画、光の既定値

`model` は省略時 `cube`。ほかに `bottom_slab`、`top_slab`、`cross`、`stairs`、`fence` がある。
`layer` は省略時 `opaque`。ほかに `cutout`、`translucent` がある。
花などの `cross` を cutout 描画する場合は `layer = "cutout"` を明示する。
箱の座標、草花の箱、階段の角とフェンス接続の計算は Rust に残す。

| フィールド | 省略時の値 |
| --- | --- |
| `occludes` | モデルが `cube` かつレイヤーが `opaque` の場合だけ true |
| `solid` | `cross` の場合だけ false、それ以外は true |
| `cull_same` | モデルが `cube` かつレイヤーが `translucent` の場合だけ true |
| `opacity` | 解決済みの `occludes` が true なら15、それ以外は0 |
| `emission` | 0 |

`occludes` は遮蔽、`solid` は衝突、`cull_same` は同一状態との内部面の除去を表す。
光の減衰 `opacity` と発光 `emission` は0〜15。
各値を明示すれば既定値を上書きできる。例えば空気は `occludes = false`、`solid = false`、
ガラスは `layer = "cutout"`、`cull_same = true`、水は `layer = "translucent"`、
`solid = false`、`opacity = 1` とする。
葉も `layer = "cutout"`、`cull_same = true` を明示し、同じ葉の内部面だけを除く。
葉の `opacity = 1` は維持し、光の計算や木を含む地形の生成結果は変わらない。

### 複数状態

`states` は省略すると性質なしの1状態。複数状態なら配列順に `id + index` を割り当てる。
各項目の `properties` は順序付きの `[キー, 値]` の配列。
`model`、`occludes`、`opacity` を状態単位で上書きできる。
明示値の優先順位は状態側、ブロック側、既定値の順。
既定値は各状態の最終的なモデルとレイヤーから計算する。
そのためハーフブロックは次のようにモデルと性質だけ指定すればよい。

```toml
[[blocks]]
name = "oak_slab"
id = 14
texture = "oak_planks"
states = [
  { properties = [["type", "bottom"]], model = "bottom_slab" },
  { properties = [["type", "top"]], model = "top_slab" },
  { properties = [["type", "double"]], model = "cube" },
]
```

文字列表現は `oak_slab[type=bottom]` の形式。キーの順序もデータどおりになる。
階段モデルは `facing` が north/south/west/east、各方向の `half` が bottom/top の順で8状態を持つ。
隣接形状の計算がこの順序を使うため、ビルド時にも検証する。

重複した名前・テクスチャ・状態・性質のキー、未知のモデル・レイヤー・テクスチャ・tint の面名、
範囲外の光の値、不明なフィールド、TOML 構文エラーもビルド時に拒否する。
既存の40状態は移行前に採取した `crates/world/tests/registry-v1.txt` と比較する。
新ブロックを追加する段階では、新しい期待値を別途追加し、既存状態の互換性を維持する。

### バイオーム

`biomes.toml` に `[[biomes]]` を追加する。出力は `world::biomes::BIOMES`。

```toml
[[biomes]]
name = "mild_meadow"
surface = "grass_block"
subsurface = "dirt"
grass_color = [124, 184, 84]
leaves_color = [88, 152, 70]
water_color = [62, 128, 200]
temperature = [0.25, 0.8]
humidity = [0.3, 0.85]
```

地表 `surface` とその下 `subsurface` のブロック名は先頭状態に解決する。
草・葉・水の色は必須の RGB 3 バイト（各成分0〜255）、温度・湿度は0〜1の目安の範囲。
名前の重複、不明なブロック、逆転した範囲や範囲外の値を拒否する。
全13バイオームの色は自作の初期値。色は地形の選択・地表素材には影響しない。
クライアント描画への適用は次のタスクで行う。

## ノイズ

`noise::GradientNoise::new(seed)` は `jmath::Xoroshiro128PlusPlus::from_seed` を使い、
0〜255 の表を Fisher–Yates でシャッフルする。交換先は64ビット乱数の棄却法で一様に選ぶ。
座標を floor で格子点と相対位置に分け、軸ごとに256で折り返す。
ハッシュは `p[(p[(p[x] + y) mod 256] + z) mod 256]`。2D は z=0 とする。
軸方向の周期は256格子。

2D の勾配は `(±1, 0)`、`(0, ±1)` と `(±0.5, ±0.5)` の8方向。
3D はゼロ成分を1つ持つ `(±0.5, ±0.5, 0)` の成分の並べ替えによる12方向。
表から勾配を選び、各角からの相対位置との内積を計算する。
補間係数は `fade(t) = t³(t(6t - 15) + 10)`、補間は `lerp(t,a,b) = a + t(b-a)`。
x、y、z の順に補間する。端点で1階・2階の微分がゼロになり、格子境界で滑らかにつながる。
勾配の L1 長を1に抑え、値は [-1, 1] 内。格子点ではゼロになる。

`noise::Fbm::new(seed, octaves, lacunarity, persistence)` は各オクターブに独立した順列と
各軸の非整数オフセットを持つ。`Xoroshiro128PlusPlus::from_seed(seed)` から、各オクターブについて
`next_long()` を1回取り `GradientNoise` の派生シードにし、続く3回を x/y/z のオフセットに使う。
オクターブ数を増やしても既存のオクターブのシードとオフセットは変わらない。
各オフセットは乱数を `u64` とした `r` から
`4096 + (r & 65535) + 1/8 + ((r >> 16) & 65535)/131072` で作る。
整数部分は格子周期の16倍以上、端数は [1/8, 5/8) の正確な二進分数となる。
評価座標は `座標 × 周波数 + オフセット` の順で計算する。
別の順列でオクターブ間の模様を分離し、非整数のずらしで原点や整数座標が全オクターブの
格子点に揃ってゼロになる問題を防ぐ。1オクターブの fBm も、ずらしていない `GradientNoise` とは異なる。
周波数と振幅は1から始め、各オクターブでそれぞれ lacunarity と persistence を掛ける。
結果は振幅の合計で割って正規化する。オクターブ数は1〜32、周波数倍率は有限かつ1以上、振幅倍率は0〜1。
基本周波数は呼び出し側で座標に掛ける。全オクターブで周波数とオフセットを適用した後の座標が有限で、絶対値が 2^52 未満になる入力を使う。
大きすぎる座標では浮動小数点の精度により格子内の位置を失う。

浮動小数点の演算は f64 の加減乗除と floor のみ。三角関数、sqrt、powf、融合積和は使わない。
式の評価順を保ち、native と WASM の双方で同じ丸め結果を得る。
固定シード・座標の `to_bits`、範囲、格子点、連続性、シードによる変化をテストする。
fBm では lacunarity=2 の原点・正負の整数座標で値がゼロに固定されないこと、
各オクターブを同じ周波数で評価しても値が異なることを検証する。
`GradientNoise` 単体のビット固定値は維持する。

## Terrain: 地形の形 (issue #19)

`crates/worldgen/src/terrain.rs` にパラメータを名前つき定数としてまとめた。
`TerrainGenerator::new(seed)` が用途別の fBm 順列表を準備する。
シードは `mix_stafford13(seed as u64 ^ 用途別の *_SALT)` から派生させる。
大陸・起伏・細部・3D密度は互いに異なる塩を使う。
`TerrainGenerator` を呼び出し側で保持すれば、チャンクごとの表の再構築を避けられる。
従来の `generate(Generator::Terrain, seed, cx, cz)` と `surface_y` も利用できるが、
この簡便な関数は呼び出すたびに表を作る。Server は Terrain の場合だけ準備済みの構造体を保持し、
チャンク生成で使い回す。出現地点は起動時に一度計算して保持する。
可変グローバル状態・スレッドローカル・HashMap は使用しない。

### 基準高度と密度

以下は全て自作の式とパラメータ。S(t) は t を [0,1] に clamp した後の `t*t*(3-2*t)`。
N は用途ごとに独立した正規化 fBm、座標の単位はブロック。

```text
c = 3 * N_continent(x/1100, z/1100)
l = S((c + 0.12) / 0.45)
r = S(3 * N_relief(x/470, z/470) + 0.35) * l
d = N_detail(x/95, z/95)
raw = 64 + 85*c + 110*r*r + 8*d
base = soft_height(raw)
strength = 2 + 36*r*r
density = base - y + strength * N_density(x/38, y/19, z/38)
```

| 定数 | 意味 |
| --- | --- |
| `CONTINENT_SCALE=1100`, `RELIEF_SCALE=470`, `DETAIL_SCALE=95` | 大陸、山地、細部の基本波長。数百〜数千ブロック単位で海・海岸・平地・丘・山を切り替える |
| `CONTINENT_GAIN=3`, `RELIEF_GAIN=3` | 正規化ノイズの値を地形分類に適した幅へ拡大 |
| `LAND_OFFSET=0.12`, `LAND_WIDTH=0.45` | 海から陸へ起伏を有効にする遷移範囲 |
| `RELIEF_OFFSET=0.35` | 平地と山地の比率を調整 |
| `BASE_CENTER=64`, `CONTINENT_HEIGHT=85` | 基準高度と大陸による海底・陸地の高度差 |
| `RELIEF_HEIGHT=110`, `DETAIL_HEIGHT=8` | 山の高度と細部の凹凸の強さ |
| `BASE_MIN=20`, `BASE_MAX=180` | 基準高度が漸近する下限と上限 |
| `BASE_LOW_KNEE=50`, `BASE_HIGH_KNEE=110` | 高度の圧縮を始める接続点 |
| `DENSITY_MIN=2`, `DENSITY_RELIEF=36` | 平地で弱く、山地で強い3Dの変形 |
| `DENSITY_XZ_SCALE=38`, `DENSITY_Y_SCALE=19` | 3D変形の水平・垂直の基本波長。山地では密度が上下に反転し、崖・張り出しができる |
| `CONTINENT_OCTAVES=3`, `LOCAL_OCTAVES=2` | 大陸と、それ以外のノイズのオクターブ数 |
| `FBM_LACUNARITY=2`, `FBM_PERSISTENCE=0.5` | fBm の周波数倍率と振幅倍率 |
| `CELL_XZ=4`, `CELL_Y=8`, `Y_POINTS=49` | 補間セルの幅・高さと、-64〜320 の垂直格子点数 |
| `SEA_LEVEL=56` | この地形独自の海面 (公開定数) |
| `BEACH_HEIGHT=2` | 浜の最高高度は海面+2。下層厚さはレシピの `depth` (上限8) |
| `SPAWN_RADIUS=512`, `SPAWN_STEP=16` | スポーン探索の最大範囲と間隔 |

密度はワールド座標に揃えた水平4×垂直8×奥行4の格子点だけで評価する。
地形本体は5×49×5点。斜面判定用の外周セルを含め7×49×7=2401点 (各点で2オクターブの3Dノイズ) を持ち、
x、z、y の順に三重線形補間する。2D の基準高度と強さは外周を含む水平格子点ごとに49回求める。
負座標にも Euclidean division を使い、隣のチャンクと同一の格子面を共有する。
密度>0を固体とする。密度の最大値は `180-y+38` 以下なので、y=218以上は空気。
山の上にはワールド上端319まで100ブロック以上の余裕がある。
海域では l が小さく強い3D変形が無効になるため、海底を高めに維持する。
格子点の下限評価から確実に固体となるセクションのみ石で一括充填し、レシピの実際の最大下層厚さ (現在3層) を残す。外周セルは斜面の高さ判定だけに使い、石の一括充填の下限評価には地形本体の5×5格子を使う。
演算は f64 の加減乗除・floor・比較・clamp に限り、libm や融合積和は使わない。

### 水・地表・スポーン

海面以下の非固体は、張り出しの下も含め WATER。MIN_Y=-64 は BEDROCK。
バイオームごとの地表レシピは下記「気候とバイオーム」を参照。
固体でない部分を地表材で埋めることはなく、レシピの深さより下は STONE。
洞窟、鉱石、木は後述の段階で追加する。
`surface_y` は従来の密度から上から最初の固体の高さを返す。氷を除いた地形本体の高さであり、
寒い海では固体の氷が海底より上に存在するが、この API の値は変えない。

`spawn_point(gen, seed)` は足元の座標を返す。
Terrain では原点、次いで16ブロック刻みの正方形の外周を、半径512まで順に調べる
(各外周は z、x の昇順)。海面より高い最上部の固体の1ブロック上を選ぶため、
頭上2ブロックは必ず空気となる。見つからない場合は原点の地表と海面の高い方+1。
Flat と DebugHills は従来どおり原点の地表+1。Server は `worldgen::spawn_point` で起動時に
一度計算し、プレイヤーの x/z を列の中心 (+0.5) に置く。

### 検証・指紋・性能

Rust テストは生成の再現性・シード差、負座標を含む隣接チャンクの格子面の完全一致、
境界と内部の高度差の比較、全列の surface_y 一致、水・岩盤・地表材・セクションのカウンタ、
張り出しと石の天井、スポーンを確認する。
分布は seeds=0,2026,-71 について x/z=-2048..2048 を64ブロック刻みで調査し、
海の割合を15〜65%、y>140の山が存在すること、海底y>=1、最高高度y<=218を固定する。
修正後の計測値はそれぞれ海37.6%/31.0%/40.0%、高さ29〜162/27〜162/26〜157だった。

y=-64..319、z、x の順でブロックID (u16 little-endian) を FNV-1a に投入する。

### 山頂と海底の圧縮

硬い clamp は大きな領域を同じ高度に切りそろえるため、両側を次の有理式に置き換えた。
接続点の値と傾き (1) は中央の直線と連続する。加減乗除と比較だけを使う。

```text
raw < 50:  base = 20 + 30*30 / (50 - raw + 30)
raw > 110: base = 180 - 70*70 / (raw - 110 + 70)
otherwise: base = raw
```

### ジェネレーターの永続化と既存ワールド

| id | 名前 | 用途 |
| --- | --- | --- |
| 0 | Flat | クラシックフラット |
| 1 | DebugHills | 従来の仮の丘陵、決定論の台本、旧ワールド |
| 2 | Terrain | 新規ワールドの既定 |

未知の数値 id は Rust 側で従来どおり DebugHills に解決する。
ローカルでは `?gen=flat|hills|terrain` で新規ワールドの生成方式を選択する。
指定なし・不明な名前は Terrain。保存済みの seed と generator は URL より優先される。
OPFS の meta.json に数値の generator を起動前に保存する。既存 meta に generator がない場合は1を補う。
初期化の読み取り・判定・書き込みは、インポートと共通のワールド単位の Web Lock
(`mcworld-import-${world}`) の中で行う。ロック取得後に読み直し、既存値があればそれを返す。
初期化処理自体は書き込みキューに積まず、ロック内から既存のキュー経由で書き込む。
インポートは取得済みのロック内から直接書き込み、初期化を再入させない。
Web Locks がない環境ではタブ間の排他を保証できないため、OPFS を開かず保存なし
(`persistence: off`) で遊ぶ。初期化・インポートもロックなしでは実行しない。
このアプリに必須の WebGPU に対応するブラウザーには Web Locks もあるため、
排他を保証できない保存経路は設けない。初期化後の再読み取りは、ロック内での保存確認として行う。
新しい meta にはクライアントの選択値を保存する。`.mcworld` は引き続き版1のまま、meta.json の
追加フィールドとして generator を保持する。generator のない旧アーカイブは1として読み込み、
読み込み先に補完した meta を保存する。world-import の保存完了・移動の手順はそのまま使う。

DO では seed が既にあれば保存値を使い、generator だけなければ1を補って保存する。
seed がなければ新規ワールドとして2を保存する (古い generator だけが残っていても2を優先)。
seed と generator は同じ SQLite トランザクションで確定する。evict は両方を残して再起動する。
seed を削除するワールドリセット処理は現在ない。
F3 と debug stats は保存済みの実際のジェネレーター名を表示する。
ローカルは worker の ready、DO は接続時の worldInfo テキストフレームでホストから通知し、
ゲームのバイナリパケットや既存のシナリオ指紋は変更しない。

E2E は Terrain を既定のまま使い、出現地点の陸・頭上の空気、描画、移動、設置、保存・再読み込みを検査する。
地表と下層のブロック名を実際のレジストリから読み、設置先は地形の凹凸に依存しない出現地点の列の頭上に置く。
旧来の固定原点への依存を避け、tick-probe も出現地点の列にマーカーを置く。
今回の環境では E2E を実行せず、`node --check tools/e2e.mjs` と tick-probe の構文検査まで行った。
edge の型生成 (`cf workers types`) は環境のローカル待受け制限 (`listen EPERM 127.0.0.1`) により失敗し、
生成型がないため edge の tsc は完了できなかった。client の tsc は成功した。


## 気候とバイオーム (issue #19)

分類・名前・数値・地表の構成は自作。他のゲームの一覧・配置表・データや逆コンパイルは使用しない。
要求に挙がった種類を全て区別するため、海3・浜2・陸6・山2の計13種類とした。
`data/registry/biomes.toml` が気候の範囲・地形の種類・地表レシピの定義元。
範囲は矩形の内外判定ではなく、**中点を気候の代表点**として使う。
同じ地形の種類の中で、温度と湿度の二乗距離の和が最小のものを選ぶ。同距離なら TOML の定義順。
従って範囲の間にも必ず1種類が決まり、範囲の重複も曖昧にならない。
ビルド時に全地形種の定義の存在、範囲の有限性・順序・0〜1、下層厚さ0〜8、
全ブロック名を検証し、不正な名前はビルドエラーにする。省略した `slope` は石。

### 地表と新ブロック

各列の最上部の固体1層を `surface`、下の `depth` 層を `subsurface` に置換する (現在は全て3層)。
海底は表層から下層まで `underwater` を使う。
陸では東西南北いずれかの列と高さが3以上違えば、表層と下層を `slope` にする。
その下は石。密度が負の空洞はこの処理で埋めない。
砂漠は砂+砂岩、雪原は雪+土、雪峰は雪+石。森と湿地は別バイオームだが今回は草+土。
寒い海は海面 y=56 の水1層を氷に置換する。雪は既存の地表固体を置換し、上に積まない。
斜面の隣接高さはチャンク外周も含め同じワールド座標で計算し、生成順序・チャンク境界に依存しない。

状態ID 40〜44に `snow_block` / `sandstone` / `gravel` / `ice` / `coarse_dirt` を末尾追加。
既存のID 0〜39とテクスチャレイヤー0〜17は維持した。砂岩は上面・側面・底面に異なる16×16の模様を使う。
氷は半透明アルファ190、solid、cull_same、opacity=1。既存の当たり判定・光・メッシュの経路を使う。
選択画面はレジストリから自動で追加される。バイオーム別の頂点カラーは今回変更しない。

### API・表示・検証

`TerrainGenerator::biome_at(x,z)` と `worldgen::biome_at(gen,seed,x,z)` は列の BiomeId を返す。
Flat/DebugHills は既存の `mild_meadow` (ID 0)。

`TerrainGenerator::biome_cells(cx,cz)` と `worldgen::biome_cells(gen,seed,cx,cz)` は
チャンクの4×4セルを `[BiomeId; 16]` で返す。セル `(i,j)` は
`(cx*16+4*i+2, cz*16+4*j+2)` の `biome_at` と一致し、配列の添字は `j*4+i`。
5×5の密度格子を一度だけ計算し共有する。連続呼び出しでは `TerrainGenerator` を保持し、
メソッドを直接呼べばシードごとのノイズテーブル初期化も省ける。Terrain 以外は全セル0。

クライアント WASM の `client_biome_colors()` は `client_new` 後に呼び、
`client_out_ptr()` に ID 順の草RGB・葉RGB・水RGB（1バイオーム9バイト）を出力し、バイト数を返す。
`tint_biome_cells(seed: i64,generator: u32,cx: i32,cz: i32)` はワールド状態なしで呼べる。
専用の `tint_out_ptr()` に16個のIDを1バイトずつ出力し、16を返す。
IDがu8に収まることはコンパイル時に検査する。直近のシードの `TerrainGenerator` を保持し、
シードが変わると置き換える。非Terrainの呼び出しではキャッシュを変更しない。
各ポインタの結果は対応する出力バッファへの次の書き込みまで有効。
色・セルはサーバーから送らず、プロトコル・保存形式・サーバー WASM ABI は変更しない。

画面側は256×256×3層（草・葉・水）のRGBA8の色の地図を持ち、1テクセルを4×4ブロックのセルとする。
座標は1024ブロックで折り返し、64×64チャンクの各スロットに元のチャンク座標を記録する。
カメラの描画距離+1チャンクの範囲を近い順に、前フレームからの経過時間の8%を予算として更新する。
予算は1〜10msに制限する（60fpsで約1.3ms、8fpsで10ms）。
更新したチャンクの4×4テクセルは草・葉・水の3層をまとめ、1チャンクにつき1回GPUへ転送する。
リセット時も256×256×3層を1回で転送する。
頂点シェーダーで整数の原点を1024で折り返してからローカル座標を加える。
線形補間・repeatサンプラーで斜め±1テクセルの4点をレベル0で平均し、頂点間で補間した色をフラグメントに掛ける。
シード・ジェネレーター変更時は全スロットを無効にし、既定色で地図を初期化する。
Terrain以外とジェネレーター未確定時はセルを計算せず、草・葉・水には既定色を使う。
`window.__mc.tint(x,z)` は計算済みセルのバイオームIDとぼかし前のRGBを返し、未計算ならnullを返す。


Server が受理したプレイヤー位置からバイオーム名を求め、WASM の `server_client_biome` で UTF-8 を取得する。
ホストとのABIは追加exportを認識するため3から4へ更新。ゲームのバイナリパケットは変更しない。
ローカル worker と DO の両方が `ServerStats.biome` を送り、F3と `window.__mc.stats().server.biome` に表示する。
DO は毎20 tickにプレイヤー別の stats テキストフレームを送る。
E2E は stats に名前があることを待ち、足元のブロック名を取得するので雪・砂・礫のいずれでも同じ検査を行う。
この作業では E2E・dev サーバーは起動せず構文検査のみ。

Rust では気候101×101格子の全地形種被覆・同距離時の順序、同じシードの再現性、
3シード×512×512列 (32ブロック間隔、約16 km四方) の全バイオーム出現と陸の単独70%未満、
全バイオームの非急斜面の実チャンク地表、砂岩・雪・氷、負座標とチャンク境界、岩盤・水・下層を検証する。
変更前の `surface_y` を3シード×65×65点で採った指紋 `f3c5543374b0b4b8` も維持する。
ブロックの互換性テストは旧40状態のスナップショットをそのまま照合し、新5状態は別途検証する。

### チャンクをまたぐ地物(木)

Terrain の木は独自の規則で配置する。既存ゲームの形・配置アルゴリズム・数値や
逆コンパイルしたコード・ゲームデータは使わない。実装は `crates/worldgen/src/trees.rs`。
Flat / DebugHills のブロックと既存の台本・ノイズは変更しない。

XZ を4×4ブロックの区画に分け、区画座標は負座標も含め `div_euclid(4)` で求める。
区画ごとに高々1本。seed・区画座標・専用 salt `19ac62e7d403b58f` を
`mix_stafford13` で混ぜ、区画内の整数オフセット0〜3、抽選値 r∈[0,1)、高さ・形の変化を決める。
生成先のチャンク座標を乱数に混ぜず、共有状態も持たない。

地形の生成後、内部4×4区画と外側1区画を合わせた **6×6=36区画** を調べ、
このチャンクに入るブロックだけを書き込む。r が全バイオームの最大密度以上なら高さ計算前に除外する。
根元と四方の高さは、既存の外側1セル付き7×7密度格子を共有して求める。
各列は `surface_y` と同じワールド格子点・同じ補間式を通す。
根元がチャンクから半径以内にある候補だけを調べるため、四方の高さも外周格子内に収まる。
樹冠が格子の外まで届く場合は、高さサンプラーで足りない格子点を補う。
樹冠の最大XZ半径は定数で3以下、区画幅未満に固定し、コンパイル時assert・
ブロック列挙時のdebug_assert・形と境界のテストで保証する。枝と先端の葉もこの範囲に収める。

幹と枝の原木は空気・葉を置き換え、葉は空気だけを置き換える。
地形・水・氷を保護し、同種の木のブロックは同じ状態IDなので、区画の調査順に依存しない。
テストでは外側1チャンクまでの区画から全ブロックを独立に列挙し、逆順に配置した参照結果と
3シード×5×5チャンクの全ブロックを比較する。チャンクの生成順も逆にして照合する。

根元の地質の地表が海面より高く、四方との高さ差が全て3未満で、抽選が密度未満のときだけ候補になる。
地表はバイオームの surface に一致する草ブロック・粗い土・雪ブロックに限る。
砂・砂利・石の上には生えず、木の最上部がワールド上限未満に収まることも確認する。
`bare_ridge` はデータに密度を持つが、surface が石なので現在は木が生えない。

3項目ともレジストリの必須項目。build.rs は密度0〜1、none の密度0・高さ[0,0]、
それ以外の高さ `3 <= min <= max <= 12` を検証し、未知の形とフィールドを拒否する。
幹と枝は `oak_log`、葉は `oak_leaves` を使う。形と葉の抽選には区画の variation を
`mix_stafford13` で混ぜた値を使う。

- `round` の樹冠は、幹が5段以下なら下から半径 1, 2, 2, 1 の4段、
  6段以上なら 1, 2, 3, 3, 2, 1 の6段。最上段は幹上端の1段上に置く。
  幹が7段以上なら0〜2本の枝を出す。各枝は樹冠の下端より1〜2段下から四方のいずれかに
  原木を1〜2個伸ばし、先端に半径1の葉と、その1段上の十字を付ける。
- `round` の約40本に1本は大きな木になる。幹はバイオームの通常の最大値より3〜5段高く、
  現行のバイオーム設定では樹冠の半径を下から 1, 2, 3, 3, 3, 3, 2, 1 とし、
  枝を2〜3本出す。最上部がワールド上限未満に収まることを、抽選後の高さで確認する。
- `cone` は最大半径1〜2の細い型と、下端が半径3の広い型を抽選する。
  幹の高さの半分を切り捨てて2を足した段数を使い、上に行くほど半径を下げる。
  1段おきに半径をさらに1小さくし、幹上端の上には葉を縦に1〜2個置く。
- `broad` は低い幹の上に半径3の段を1〜2段、その上に半径2の段を1段置く。

樹冠の各段は `dx*dx + dz*dz <= r*r + r` の整数判定で円にする。
`round` と `broad` の各段では、一つ小さい半径の円より外側にある葉を
位置と段ごとのハッシュで約1/4間引く。半径1では中央の十字をすべて残す。
ふちは内側の葉と面で接している。樹冠が斜面と重なる場合は、地表より上の幹と枝を起点に
面づたいの経路を調べ、原木から6歩以内に届く葉を配置する。

坑道の周囲では、従来の樹形で通行空間に触れる候補を引き続き除外する。
新しい樹冠や枝が坑道内や出口のジャンプ空間に入るときは、同じ根元に従来の樹形を使う。
大きな木がワールド上限に収まらないときも、従来の樹形が収まればそちらを使う。

`surface_y` は引き続き地質の地表を返し、木を含めない。`biome_at` / `biome_cells` も変更しない。
スポーンは既存の正方形リングの候補順を保ち、実際に生成したチャンクで地表の上2ブロックが
空気であることを確認する。幹・葉に重なる候補は飛ばす。探索失敗時は半径を広げ、固体の足場と空気2ブロックがある候補を探す。E2E はバイオーム色の検査用 Terrain・seed=2026 のワールドで、
スポーンからXZ各±24ブロックに幹・葉がそれぞれ1個以上あることをデバッグAPIで確認する (本環境では未実行)。

保存済みのチャンクは再生成されず、古い木の形のまま残る。保存済みチャンクと新規チャンクの
境界をまたぐ木では、片側が古い形、もう片側が新しい形になり、樹冠や枝が合わなかったり
欠けたりする。原木から6歩以内につながらない葉はいずれ消滅する。
区画ごとの根元の座標は共通なので、幹の列は境界でずれない。

## 洞窟と地下水

`crates/worldgen/src/caves.rs` は一般的な3次元ノイズのしきい値判定で洞窟を作る。
入口の坑道は `crates/worldgen/src/entrances.rs` で別に作る。
規則・数値・salt は独自に決め、既存ゲームの生成コード・データ・数値は使わない。

通常の洞窟は、独立した salt の1オクターブ `Fbm` を3本使う。

- トンネル: 横58・縦29ブロックのスケールの `a`, `b` に対して
  `a*a + b*b < 0.036*0.036` の場所を削る。
- 空洞: 横37・縦26ブロックの `c` に対して
  `c > 0.25 + clamp((y+56)/160, 0, 1)*0.10` の場所を削る。

3本ともワールド座標にそろえた4ブロック格子で評価し、XZ、Yの順で線形補間する。
負座標も `div_euclid` で同じ格子にそろえる。生成時は `MIN_Y+6` から最大 `top-6` までの
格子を用意し、列ごとのXZ補間を使い回す。各ブロックで直接ノイズを評価しない。
トンネルも空洞も、区域にかかわらず `y > top-6` と `y < MIN_Y+6` を常に保護する。
以前の `roof_depth` による制限緩和は廃止した。
通常洞窟が削った位置は `y > -41` なら空気にする。
`y <= -41` では列の地域に応じて地下水または溶岩源を置き、地域の境目には黒曜石を置く。
地下水と溶岩源は生成直後には流れない。

入口の区域は、以前と同じ2次元・1オクターブノイズ、salt `8a47ef1062bcd395`、
スケール193ブロックを使う。しきい値 `ENTRANCE_THRESHOLD` は **0.22**。
seed=2026の原点から200ブロック以内の陸では、このノイズの最大値が約0.224だったため、
最寄り200ブロック以内という今回の目標に合わせて0.27から調整した。
区域は通常洞窟の保護を緩めるためには使わず、坑道の始点の選別に使う。

区域の陸面積比は、XZ各 -4096..4096 (上端を除く)、32ブロック間隔の256×256列で測定した。
分母は `top > SEA_LEVEL` の陸、分子はそのうちノイズが0.22を超える列。

| seed | 区域の陸列 / 陸列 | 割合 |
| --- | ---: | ---: |
| 2026 | 4,842 / 38,758 | 12.4929% |
| 0 | 5,175 / 39,334 | 13.1566% |
| -71 | 4,966 / 39,930 | 12.4368% |

坑道はXZの32×32区画ごとに決める。seed・区画座標・専用 salt `6e31a954b8072dda` を
`mix_stafford13` で混ぜ、区画内の始点、抽選、4方向の向き、形の乱数を得る。
抽選率は **65%**。当選し、始点のノイズがしきい値を超え、`top > SEA_LEVEL+2` のときだけ作る。
チャンクの座標や生成順を乱数に混ぜず、共有する可変状態も持たない。

始点の地質の `top` から、主方向に1ブロック進むごとに0.75・0.775・0.8のいずれかで下降する。
横には最大1ブロック、8歩かけてゆっくり揺れる。横断面の半径は1.75・2.0・2.25のいずれか。
下降量24〜27ブロックに達する最初の歩で終わり、上限は36歩。

各XZ列の主方向への整数進行量をsとし、元の床候補を
`s >= 0: top - floor(slope*s)`、`s < 0: top - s` にする。
主方向の中心列で得た地質の地表を上限とし、前後から隣列との差が1ブロック以内になるまで
床候補を下げる。これにより、谷へ向かう区間でも空中に床を作ることなく、登れる段差を保つ。
始点側は、地表に接続できる最短の登り口を0〜36歩の範囲で選ぶ。
遠方の谷が始点の床を不必要に下げることを避け、範囲内で乾いた地表に接続できない候補は除外する。
地質の地表は `surface_y` と同一の格子・補間で取得し、連続列の密度サンプルを使い回す。
床を確定した後、断面の端を含む各列について、床+1〜床+4と地形の水位
(`top+1`〜`SEA_LEVEL`、海面の氷を含む) が重なる候補は除外する。
横4方向の隣列の水位と接する場合も、`removable` の水際保護で通路が残るため除外する。
既存の列高さ・密度サンプルのキャッシュと、重複を除いた断面の列一覧を使って判定する。

重なった断面も同じ列では同じ床を使うため、後続の断面が手前の踏み段を削らない。
床の上4ブロックを空け、身長1.8とジャンプに必要な頭上空間を確保する。
形の判定・列挙ともに加減乗除・floor・比較だけを使う。

坑道が削るのは石・草・土・砂・雪ブロック・砂岩・砂利・粗い土だけ。
通常の洞窟などで床が空気になっている場合は、**その列の地質の地表以下の場合だけ**石で補う。
判定には生成時の18×18の `heights` を使う。始点より後ろや、谷に向かって通路が空中へ出る列も同じ規則で、
元の地表より上には石を置かない。これは全坑道を削った後に行い、他の坑道の削除で床が欠けることも防ぐ。
水・氷・岩盤・木などは置き換えない。床の補完も空気だけを石にする。
床補完で他の通路の頭上をふさがないよう、交差する原候補の床に1〜4ブロックの差があるときは、
区画の `(qz,qx)` 順で後の候補を除外する。近傍±3区画の原候補だけで決めるため、生成順に依存しない。
抽選・向き・曲がり・半径・元の中心線の下降率と深さ・入口ノイズは維持する。

床や断面の端も含め始点から水平 **40ブロック以内** (`MAX_ENTRANCE_REACH=40`)。
コンパイル時assert、列挙時のdebug_assert、全ブロックのテストで保証する。
生成側はチャンクを40ブロック広げた範囲から届く全区画を調べ、自分に入る部分だけ書き込む。
木の判定用にはさらに樹冠半径の3ブロック分を広げ、同じ坑道の記述を共有する。
`y <= -41` は変更せず、この下限が `MIN_Y+6` 以上であることもコンパイル時assertで確認する。
床を地形に合わせてさらに下げる場合も、地下水面より上という削除・補完の下限を守る。

`physics` はworldgenの **dev-dependencyのみ**。
実際の `physics::Player` と、クライアント・サーバーと同じレジストリ形状を使う `physics::BlockWorld` で、
最も低い床から通常歩行とジャンプだけで地上へ戻れることを検査する。
全3半径・4方向・左右の曲がり・3下降率・平地と勾配±0.5/±1の計360条件で、
2400 tick以内に始点の外の地表へ立てることを確認する。
さらにseed=2026・0・1・-71の原点周辺の全坑道を距離順に検査するため、2026の最寄り5つも含む。
この360条件と4シードの脱出条件・制限tick数は、地表以下だけの床補完に変更した後も維持する。
4シードでは800×800列を覆う全区画の採用坑道について、生成後の通行空間に水・氷が残らず、
隣接水の保護に該当しないことも検査する。人工の凍結海岸では、中心列・断面の端・
断面の外の隣列に水と海面の氷を置き、候補の棄却と水位境界を直接検査する。
別の回帰テストで、人工の平地・斜面と2026の最寄り5坑道において、地表より上に石を追加しないことを検査する。
指摘された `(198, z=22/23)` の列の地表上3ブロックが空気であることも確認する。
空気と床を独立に列挙した参照結果との比較と、逆順のチャンク生成も維持する。

通常洞窟と坑道の両方で、横4方向の隣列に `top_n < y && y <= SEA_LEVEL` の地形の水があれば削らない。
チャンク外の隣列も既存の外側1列付き18×18高さから判定し、`is_cave` にも同じ規則を使う。
seed=2026・0・-71、cx/cz=-10..=10の各21×21チャンクで、
地形の水に横接する洞窟・坑道の空気 (`y > -41`) が0個であることをテストする。

生成順は **地形→地表素材→洞窟（地下水・溶岩・黒曜石を含む）→坑道→鉱石→木**。
鉱石は石だけを置き換えるため、壁に残る石には配置できる。
木は根元の地質の `top` が洞窟または坑道で削られるなら木全体を除外する。
幹・樹冠のいずれかが坑道の通行空間に入る木も除外し、後から葉でジャンプ空間をふさがない。
ワールド座標と坑道の記述で判定するため、隣チャンクの樹冠や生成順にも依存しない。
スポーンは従来の正方形リングの順を保ち、実際の生成チャンクの `top` が固体で、
その上2ブロックが空気の候補だけを採用する。穴の中や穴の真上には出さない。
見つからなければ探索半径を倍にする。
`surface_y`・`biome_at`・`biome_cells` は削る前の「地質の地表」の意味を維持する。

入口の計測例:

```sh
cargo run --release -p worldgen --example terrain_map -- 2026 --entrances 400 10
```

XZ各 -400..400 (上端を除く) の **800×800列** を調べる。
`top > SEA_LEVEL+2` で地質の `top` が空気の列から、各列の `y <= top` に限って
空気を6方向にたどる。地上の空気で別の穴をつながず、地下でつながる穴を1成分と数える。
成分にある対象範囲の地表開口の最大 `top` と、到達した最低yの差を深さとする。
代表座標は成分内の対象開口で原点に最も近い列。結果もその水平距離順に表示する。
範囲外の地下のつながりを追うため、周囲512ブロックも生成し、外周に触れた成分数も表示する。
2026・0・1はいずれも外周接触が1成分だけで、その成分は空気の下限y=-40まで到達している。
残りの成分は外周に触れないため、範囲外で互いに合流する余地がなく、
接触成分の最低yもこれ以上下がらない。したがって下表の個数と深さ分布は境界の打ち切りで変わらない。

## 鉱石

`crates/worldgen/src/ores.rs` に独自の鉱石配置を実装した。一般的な鉱物名と自作の規則・数値だけを使い、
既存ゲームの鉱物の組み合わせ、生成コード、データ、テクスチャは参照していない。

| ブロック | ID | 中心の高さ y | 区画ごとの候補数 | 鉱脈のブロック数 | 石の上の粒 |
| --- | ---: | --- | ---: | --- | --- |
| coal_ore | 45 | 0〜140 | 9 | 6〜14 | 黒に近い灰色、角ばった塊 |
| copper_ore | 46 | -20〜70 | 5 | 5〜10 | 赤橙と緑青 |
| iron_ore | 47 | -50〜50 | 4 | 4〜8 | 黄土色と赤茶 |
| gold_ore | 48 | -60〜-5 | 2 | 3〜6 | 少数の明るい黄色 |

候補数は指定の目安6/4/4/1から、実際の地下の石に対する割合を測って9/5/4/2に調整した。
各候補は中心の高さが範囲内のときだけ採用対象になり、さらに高さに応じて抽選する。
範囲を `[low,high]` とすると、採用確率は
`0.35 + 0.65 * (1 - abs(2*y-low-high)/(high-low))`。
中央で1、両端で0.35の三角形なので、中央ほど多くなる。表の数は抽選前の上限。

ワールドを16×16×16の区画に分ける。区画座標は負座標も含め
`qx=x.div_euclid(16)`、`qy=(y-MIN_Y).div_euclid(16)`、`qz=z.div_euclid(16)`。
seed、鉱石のID、qx/qy/qz、専用 salt `73f1a9b4825cde06` を `mix_stafford13` で混ぜる。
この値だけから候補の中心オフセット0〜15、採用抽選、長さ、形の乱数を得る。
受け取り側のチャンク座標、生成順、共有状態は使わない。新しい依存・HashMap・libmも使わない。

中心から6方向のいずれかに1ブロックずつ歩き、重複しない位置を鉱脈に加える。
既に通った位置へも歩けるが、その位置は数え直さない。各軸の相対位置が
`MAX_VEIN_REACH=3` を越える歩みは採用せず、最大256歩で停止する。
コンパイル時assert、列挙時のdebug_assert、テストで届く範囲を保証する。
中心が範囲内なら鉱脈の端は最大3ブロックはみ出してよい。金は最大でもy=-2、石炭は最低でもy=-3。

生成先のチャンクでは、XZの周囲1区画を含む3×3区画と、各鉱石の中心の高さに届くY区画を調べる。
中心がチャンクから3ブロックを越えて離れていれば、歩みを列挙する前に除外する。
鉱脈のうち、このチャンクとワールドの高さ範囲に入る位置だけを扱う。
**地形→地表素材→洞窟（地下水・溶岩・黒曜石を含む）→坑道→鉱石→木** の順で生成する。

置き換え候補は鉱石処理前の `STONE` だけ。空気、水、溶岩、黒曜石、地表素材、砂岩、砂利、岩盤、既存の鉱石を保護する。
露出した石にも配置してよい。同じ位置の全候補を一時バッファで集約し、**最小のブロックID** を採用してから書く。
先に配置した鉱石を別の鉱石で置き換える方式ではないため、区画・種類の調査順に依存しない。
`surface_y`、`biome_at`、`biome_cells`、`spawn_point`、木の位置と形は変わらない。

## サーバーの外部生成モード（ABI 5）

`sim::Server::set_external_generation(max_in_flight)` で外部生成を有効にする。
`sim::Server` の既定値は 0（外部生成なし、同期生成）。ホストの既定とは別で、
`world-do.ts` は `GEN_OFFLOAD=0` 以外では外部生成を有効にする。`sim.worker.ts` は
`genworkers=0` の指定がなく、生成用 Worker の起動に成功した場合に有効にする。
メモリにあるチャンク、保存済みチャンクの読み込みを優先し、それ以外は
`stream_chunks` の近い順に生成を依頼する。待っている間も他のチャンクを送信できる。

`take_generation_requests()` は座標のキューを取り出す。取り出したあとも依頼中の集合に残り、
重複を防ぐ。依頼中の数が上限なら新たな依頼を積まず、次の tick で再試行する。
`deliver_generated(cx, cz, bytes)` は `Chunk::to_bytes` 形式を `Chunk::read` で検証して挿入する。
依頼中の `generating` にない座標は何もせず false を返す。メモリ上・保存済みのチャンクも
上書きせず false を返す。依頼中の破損データは同期生成で置き換えて false を返す。
ホスト側の生成失敗には `generate_now(cx, cz)` で同期生成できる。どちらも依頼中から外す。
`generate_now` はメモリ上・保存済み（`stored`）の座標を生成しない。保存済みなら
通常の `ensure_chunk` が保存からの読み込みを依頼するため、アンロード済みの編集も隠さない。
生成直後のチャンクは同期生成と同じく dirty ではなく、編集されるまで保存の対象にならない。
不要になった座標でも受け取り、遠方なら既存のアンロード処理で破棄する。
上限を 0 に戻した場合も依頼中の印が残る結果は受け取れるが、必要なチャンクは同期生成を再開する。
同期生成などで依頼中から外れた後の遅い結果は無視する。
`stats.chunks_generated` は生成総数、`chunks_generated_externally` は外部のバイト列を受理した数。

server.wasm の追加 ABI（版は 4 から 5）：

| 関数 | 入出力 |
| --- | --- |
| `server_set_external_generation(max_in_flight: u32)` | 0 で同期生成 |
| `server_take_generation_requests() -> usize` | `server_out_ptr()` に `[cx i32 LE][cz i32 LE]` の繰り返し、戻り値はバイト長 |
| `server_deliver_generated(cx, cz, ptr, len) -> u32` | 生成バイト列を受理すると 1、既存または破損なら 0 |
| `server_generate_now(cx, cz)` | 同期生成へのフォールバック |
| `gen_chunk(seed: i64, generator: u32, cx: i32, cz: i32) -> usize` | 生成専用、戻り値はバイト長 |
| `gen_out_ptr()` | 生成専用出力バッファのポインタ（次の `gen_chunk` まで有効） |

`gen_chunk` は `server_new` 不要で、Flat (0)、DebugHills (1)、Terrain (2) を扱う。
TerrainGenerator は直近の Terrain 用シード 1 個だけを保持する。生成出力は
サーバーやストレージの出力バッファとは独立している。
TypeScript は `ServerCore` の薄いラッパーと、同じ WASM モジュールから別インスタンスを作れる
`ChunkGenCore.fromModule(module).generate(seed, generator, cx, cz)` を提供する。
返すバイト列はコピーなので、次の生成や WASM メモリ拡張後も使える。

外部生成が無効なら従来どおりの同期生成で、決定性は変わらない。
新しい統計はシナリオハッシュに含めない。seed 2026 の現在の参照値は
シナリオ `fb44177a49e57629`、ノイズ `d5166400c68a1c45`、地形 `8a5f7c2e7b0aa3dc`。チェストの件数と内容がstate_hashに入るようになり、シナリオの値が変わった。
外部生成では到着時刻によってチャンク送信の tick が変わるが、同じ seed・generator・座標の内容は一致する。

### ホストからの外部生成

各 tick の前後に共通の `GenerationDispatcher.pump(core)` を呼ぶ。前の pump 以降に
完了した結果をコールバックの到着順（FIFO）で反映し、例外・拒否はその依頼を
`generateNow` へ戻す。その後、同時実行上限まで次の依頼を送り、超過分は FIFO で待つ。
1 件でも 5 秒の時間切れになったら dispatcher は `failed` になり、新しい依頼を出さない。
動いている依頼と待ち行列の全件を同期生成に戻し、遅い応答をすべて捨てる。
時間切れの依頼は実際には動き続け得るため、その枠を次の外部依頼に再利用しない。
ホストは外部生成を 0 に戻す。reset は失敗状態も初期化する。
非同期コールバックは世界を変更しない。reset は待ち行列と結果を破棄し、世代番号で
古い世界の遅い応答も捨てる。統計の `generation` は requested / delivered / fallback、
queued / inFlight、直近 100 件の latencyMean / latencyMax（ms）を公開する。
DO の `/debug` metrics と両ホストの `window.__mc.stats().server.generation` で確認できる。

Durable Object は同じ Worker の `ChunkGen` 入口へ `ctx.exports.ChunkGen.generate` で RPC し、
最大 8 件を並行依頼する（`MAX_GENERATION_IN_FLIGHT`）。同じプロセスで RPC が動く開発環境では、
16 件に増やすと tick 間の生成処理が増え、タイマー遅延 p99 の振れが大きくなったため 8 件に抑える。
生成専用 WASM インスタンスは isolate ごとに再利用する。
`GEN_OFFLOAD=0` で無効。それ以外・未設定は有効で、開発・本番の設定値は `1`。
入口が存在しない場合や呼び出しが一度でも失敗した場合は警告を一度出し、同期生成へ戻す。
時間切れでも外部生成を無効にする。RPC は取り消せないため、新しい依頼を出さず結果を捨てる。

ブラウザ内サーバーは生成用 Web Worker を `min(4, max(1, hardwareConcurrency - 2))` 本起動し、
待ち件数が最少の Worker（同数なら番号が小さい方）へ割り振る。依頼上限は本数 × 4
（最低 8、最大 32）で、各 Worker は複数の依頼を ID ごとに管理する。
各 Worker が生成専用 WASM を持ち、結果のバッファを
transfer で返す。Worker の起動を確認してから外部生成を有効にする。子 Worker の作成・
起動ができない環境、実行時エラーでは同期生成へ戻す。URL の `genworkers=0` で無効にできる。
時間切れと Worker エラーは共通の停止処理を通り、全生成 Worker を terminate し、
全未完了 Promise を拒否して ID 対応表を空にする。init のやり直しでも旧 Worker と
未完了の依頼を停止し、dispatcher を reset する。

同じ seed・generator・座標のチャンク内容は同期生成と同じで、到着する tick だけが変わる。
シナリオは外部生成を使用しない。プロトコル・保存形式の変更はない。
本番では生成 1 回ごとに Worker の呼び出しが増える。RPC が同じ isolate で実行される場合は
CPU の分散にならないことがあるため、呼び出し数・CPU 使用量・遅延を実測する。

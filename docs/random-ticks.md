# ランダム tick と草・葉

サーバーのゲーム tick（毎秒 20 回）で、かまどの処理の直後にランダム tick を行う。かまどと同じく、メモリにあり、いずれかのプレイヤーの表示距離に読み込み解除の余裕 2 チャンクを加えた範囲内にあるチャンクが対象。チャンクは `(cx, cz)` の昇順、セクションは下から上の順に処理する。抽選を始める時点で空のセクションは飛ばし、空でないセクションでは毎回 3 か所を選ぶ。同じ位置が複数回選ばれることもある。

シード、`game_time`、チャンクの X・Z 座標、下から数えたセクション番号、抽選番号（0〜2）を順にビッグエンディアンで FNV-1a 64 に入力し、結果を Stafford mix13 で混ぜた値を `h` とする。セクション内の X は下位 4 ビット、Z は続く 4 ビット、Y はその次の 4 ビットで決める。草の拡散には `h >> 12` をシードにした `JavaRandom` を使う。乱数の進み具合を新たに保存する必要はなく、同じワールド状態と時刻で再読み込みしても同じ結果になる。自然変化したブロックは保存対象になり、クライアントに通知され、その位置の採掘は中断される。

## 草

- 草ブロックの真上が不透明なフルキューブ（`solid && occludes && model == Cube`）なら、草は土に変わる。
- それ以外では拡散を 4 回試す。各回の相対位置は X・Z が −1〜1、Y が −3〜1。選ばれた位置が通常の土で、真上が不透明なフルキューブでも水でもなければ草に変わる。粗い土は拡散先にならない。
- サーバーは光を計算しないため、この判定に明るさは使わない。条件を満たせば洞窟の中でも広がる。

## 葉

`oak_leaves` は、面で接する葉を幅優先でたどり、6 歩以内にオークの原木へ到達できれば残る。原木に入る最後の 1 歩も数える。地形の葉と設置した葉の両方を通れ、原木は全状態が対象。探索が未読み込みチャンクに届いた場合も葉を残す。

原木の支えがない地形の葉は空気に変わる。サバイバルでは採掘時と同じ `JavaRandom(seed ^ 0x0061_7070_6c65 ^ next_entity_id)` の `next_int_bound(10) == 0` で抽選し、当たれば葉の中心からリンゴを 1 個落とす。外れた場合とクリエイティブでは何も落とさない。サバイバルで地形の葉を採掘したときは、外れた場合に `oak_leaves` アイテムを 1 個落とす。

`oak_leaves` アイテムから置く葉は `placed_oak_leaves`（状態 ID 51）。自然には消えず、サバイバルで掘ると常に `oak_leaves` アイテムが 1 個落ちる。中クリックでは両方の葉から同じアイテムを選べる。地形生成の葉は `oak_leaves` のまま。既存ワールドでプレイヤーがすでに置いた葉も `oak_leaves` として保存されており、原木の支えがなければ消えうる。

既存の状態 ID とパケットの形式は従来どおりで、プロトコルは 10。新しい保存項目はない。

## 確認

木の形のテストはシード 2026、0、−71 で生成された樹冠を検査し、各葉が面づたいに原木から 6 歩以内であることを確かめる。`tools/e2e.mjs` の `leafDecay()` は、ローカルのクリエイティブ Terrain ワールド（シード 2026、表示距離 3、時刻 6000）で出現地点の近くの木を探し、照準を確認して左クリックで幹をすべて壊す。幹の各位置から水平 ±3、高さ −1〜+3 の範囲の地形の葉が 60 秒以内に 5 個以上減り、出現地点付近の空中に右クリックで置いた葉が残ることを確かめる。タイムアウト時は既存の診断機能で状態を記録する。

決定性シナリオ（シード 2026、600 tick）の指紋は `d36da50f11b5eb81`。tick 42 に石の下の草 (32, 65, 3) が土になり、tick 371 に原木の下の草 (229, 74, −7) が土になった。tick 575 には (58, 66, −9) の草が、真上が空気の土 (58, 64, −8) に広がった。

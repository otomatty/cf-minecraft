# 体力、空腹、死亡、リスポーン

サバイバルでは体力20、空気300、満腹度20から開始する。サーバーは接続済みの生存プレイヤーをクライアントID順に処理する。判定にはサーバーが受け付けた足元座標を使う。クリエイティブではダメージ、空気の消費、空腹、回復、飢え、食事が進まない。

## ダメージと回復

| 条件 | 処理 |
| --- | --- |
| 着地 | `max(0, floor(落下距離) - 3)` ダメージ。3ブロック以下は無傷、4ブロックでは1、10ブロックでは7ダメージ。 |
| ブロックの中で窒息 | 目の高さ（足元 + 1.62）のブロックに不透明な1マス全体の衝突判定があれば、10 tickごとに1ダメージ。ガラス、葉、水、半ブロック、階段は対象外。 |
| 溺れ | 目の高さが水（水源・流れる水）なら毎tick空気を1消費する。0に達した後、空気0で水中にいる時間が20 tick経つごとに2ダメージ。水の外では毎tick空気が5戻り、300を上限とする。 |
| 奈落 | 足元が `MIN_Y - 64`（−128）を下回ると、10 tickごとに4ダメージ。 |
| 溶岩 | 足元 + 0.4 または目の高さが溶岩なら、10 tick ごとに 4 ダメージ。溶岩を離れると間隔を数え直す。 |
| 空腹による回復 | 体力が最大未満かつ満腹度18以上の状態が80 tick続くごとに体力を1回復し、疲労が600増える。 |
| 飢え | 満腹度0かつ体力2以上の状態が80 tick続くごとに1ダメージ。体力1で止まる。 |

足元の当たり判定の真下0.001ブロックに、予測と同じブロック形状で支えがあるかを調べる。空中では受理位置の最高のyを落下の起点として保持し、着地または足元が水か溶岩に入ったときに消す。地面を離れるときは、最後に地面にいた高さを起点にする。テレポートとリスポーンでは移動先のyを起点にする。移動報告が同じtickに複数届く場合も、各受理位置で最高点と着地を記録する。落下、窒息、溺れ、奈落、溶岩、疲労と満腹度の更新、回復、飢え、食事の順で処理し、体力が尽きた時点で処理を止める。

サバイバルのクライアント予測では飛行切替を無効にする。サーバーは地上から1.5ブロックを超える上昇と、空中で20 tick経っても有効な降下がないまま進む移動報告を拒否する。移動後に地面に立っていて、上昇が段差の高さ（物理の `STEP_HEIGHT`）以内なら、落下中の段差への着地として受け付ける。降下判定の最小差は0.05ブロック。通常の通信は引き続きクライアントの座標報告に基づき、未報告時の移動はサーバーで補間しない。ホストが許可したテレポートは従来どおり使用できる。

⑥-3b の泳ぎに合わせ、足元から 0.4 ブロック上の点で水中かどうかを判定する。移動後が水中の場合は上昇の確認を省き、移動後の高さを次の上昇の基準にして、滞空の記録を解除する。水から出る移動では、水中にいた最後の高さを上昇の基準にする。上昇は基準から 1.5 ブロック以内か、許容される段差への着地なら受け付け、その移動から通常の滞空判定を始める。

移動の確認では、移動後の足元に加え、水平移動より先に Y を解決する予測に合わせて、下降または同じ高さでの移動なら移動前の X・Z と移動後の Y でも接地を調べる。その位置で着地してから足場の端を越えた場合も、着地の高さを次のジャンプの基準にする。落下ダメージは引き続き移動後の足元で着地を判定する。

## 空腹と食べ物

満腹度（`food`）は0〜20の整数で、開始時とリスポーン時は20。サバイバルの生存中に次の条件で疲労を加算する。

| 条件 | 疲労の加算 |
| --- | --- |
| 毎 tick | +1 |
| 受理した移動の水平距離 | 1ブロックごとに +4。1ブロック未満の端数は次の移動に持ち越す。 |
| 採掘を完了する | +20 |
| 満腹度によって体力を1回復する | +600 |

テレポートとリスポーンによる移動は水平距離に含めない。毎 tick の疲労 +1 の直後、疲労が1200以上ある間は1200を引くたびに満腹度を1減らす。満腹度が0の間も疲労を同じように差し引く。回復で加わった疲労は次の tick で集計する。回復や飢えの条件が崩れたら、80 tick の間隔を数え直す。

サバイバルでオークの葉を採掘すると、シードと次のエンティティIDを使った決定論的な10分の1の抽選で、葉の代わりにリンゴを1個落とす。リンゴ（アイテムID 49）は満腹度を4回復する。パン（アイテムID 56）は満腹度を5回復し、小麦3個から作れる。[農業とパンのレシピ](farming.md#レシピとパン)

サバイバルで生存中、満腹度が20未満で食べ物を選択して右ボタンを押すと食べ始める。空を向いていても食べられる。狙った先が作業台やかまどの場合はブロックの操作を優先する。32 tick ごとに選択枠から1個使い、満腹度を最大20まで回復する。右ボタンを押し続け、選択枠に食べ物があり満腹度が20未満なら次の1個を食べる。右ボタンを離す、選択枠を変える、食べ物がなくなる、満腹になる、作業台やかまどを開く、死亡する、のいずれかで止まる。ブラウザーではポインターロックの解除やインベントリを開く操作でも止める。

満腹度はホットバー上の右側に表示する。食事中は照準の下のバーが1.6秒で満ち、サーバーから選択枠の個数の減少が届くと先頭から進み直す。サバイバルで満腹度が6以下のときは、クライアントの予測入力でダッシュを無効にする。サーバー側の移動検証はダッシュを判定しない。

## 死亡とリスポーン

体力が0になったら、所持品36枠、2×2、作業台の3×3、カーソルの順で空でない枠を死亡位置へ落とす。速度は `[0, 0.1, 0]`、拾得待ちは40 tick。採掘と食事を中断し、作業台・かまどの画面を閉じる。かまどの入力・燃料・出力はその場に残る。ドロップには既存のアイテムエンティティの規則が適用され、奈落では次のエンティティ更新で消える。更新後の座標が溶岩源か流れる溶岩に入ったアイテムも消え、表示していたクライアントへ `EntityRemove` を送る。

死亡中は移動、採掘、設置、クリック、アイテム投棄、ブロック使用、選択枠変更などの操作を拒否して拒否数を増やす。拾得と体力・空気・空腹の更新も停止する。接続済みかつ死亡中に `Respawn` を受け取ると、体力20、空気300、満腹度20、死因なしに戻し、出現地点へ移動して `PlayerCorrect` を送る。

## HUDと死亡画面

サバイバルのホットバー上の左側にハートを10個、右側に満腹度アイコンを10個表示する。ハートは左から、満腹度は右から満ちる。どちらも値2で1個が満ち、端数の1は半分になる。空気が最大未満になると、上段の中央に残り空気を30で割って切り上げた数だけ泡を表示する。各メーターは読み上げ用のラベルと現在値を持つ。体力が減ると、画面の端が約0.3秒赤く光る。

サーバーから死亡状態が届くと、所持品・作業台・かまどの画面を閉じてポインターロックを外し、死因と「リスポーン」ボタンを含む「やられた」画面を開く。ボタンは Enter と Space でも押せる。死亡画面の間はゲームの操作を止め、Esc を押しても画面を維持する。サーバーから生存状態が届いたら死亡画面を閉じ、ポインターロックを取り直す。

## ブラウザーE2E

`tools/e2e.mjs` の `survivalHealth()` は新規の Flat サバイバルで、満タンのハート10個から開始する。開発用テレポートで10ブロック上から落下し、体力13、満タン6個と半分1個のハート、赤い点滅を確認する。地面を掘って拾ったブロックを持ったまま40ブロック上から落下し、死亡画面の死因と着地点のドロップを確認する。「リスポーン」を押した後は、体力20、出現地点への移動、死亡画面の終了とポインターロックの復帰を確認する。

同じスクリプトの `survivalHunger()` は新規の Terrain サバイバルで満腹度20と満タンのアイコン10個を確認する。オークの葉を掘ってリンゴを拾い、10ブロックの落下とその後の回復で満腹度を減らす。空を向いて右ボタンを長押しし、食事のバー、リンゴ1個の消費、満腹度の回復、HUDの現在値を確認する。

## プロトコル10

- プロトコル9で S2C `PlayerStatus`（0x0c）を追加した。プロトコル10の本体は `health u8, air u16 BE, dead u8, cause u8, food u8`。満腹度は0〜20を受け付ける。接続したtickの `Welcome` の後と、満腹度を含む状態が変わったtickの終わりに1回送る。
- 死因は0がなし、1が落下、2がブロック内での窒息、3が溺れ、4が奈落。死亡フラグは0か1。生存時は体力1〜20かつ死因0、死亡時は体力0かつ死因1〜4。空気は0〜300。
- プロトコル9で追加した C2S `Respawn`（0x0c）は本体なし。クライアントWasmは状態を保持し、TSから `core.health`、`core.air`、`core.dead`、`core.deathCause`、`core.encodeRespawn()` を利用できる。
- プロトコル10で C2S `UseItem`（0x0d）と `StopUsingItem`（0x0e）を追加した。どちらも本体なし。TSから `core.food`、`core.encodeUseItem()`、`core.encodeStopUsingItem()` を利用できる。疲労、歩行距離の端数、回復と飢えの間隔、食事の進み具合はサーバーが保持する。

## プロトコル12

死因 5 は溶岩で、死亡画面に「溶岩で焼けた」と表示する。`PlayerStatus` とプレイヤーのデータは死亡時の死因 1〜5 を受け付ける。プレイヤーデータの形式はバージョン 5 のまま。

プロトコル13で牛の出現・移動パケットを追加した。[Mob のプロトコル](mobs.md#プロトコル13)

## プレイヤーのデータ

`inventory_data` が返すバージョン5は158バイト。先頭1バイトが版番号5で、v4の末尾に満腹度の `food u8` が続く。体力、空気、死亡フラグ、死因、満腹度は `PlayerStatus` と同じ規則で検証する。v1〜v4も受け付け、満腹度は20に戻す。v1〜v3では体力20、空気300、生存、死因なしで復元する。接続時に落下の起点を初期化し、疲労、歩行距離の端数、各処理の間隔を0、食事の状態をなしにする。枠配置の詳細は [crafting.md](crafting.md#閉じる切断保存) を参照。

シングルプレイはOPFSの `player.dat`、マルチプレイはWorldDOの `inventories` で記録する。WorldDOは切断時に `returnCrafting` を呼び、位置とプレイヤーのデータを覚えてから `disconnect` を呼ぶ。同じWorldDOへの再接続で、死亡中のクライアントも保存した状態から再開する。

# 体力、死亡、リスポーン

サバイバルでは体力20、空気300から開始する。サーバーは接続済みの生存プレイヤーをクライアントID順に処理する。判定にはサーバーが受け付けた足元座標を使う。クリエイティブはダメージ・空気消費・自然回復の対象外。

## ダメージと回復

| 条件 | 処理 |
| --- | --- |
| 着地 | `max(0, floor(落下距離) - 3)` ダメージ。3ブロック以下は無傷、4ブロックでは1、10ブロックでは7ダメージ。 |
| ブロックの中で窒息 | 目の高さ（足元 + 1.62）のブロックに不透明な1マス全体の衝突判定があれば、10 tickごとに1ダメージ。ガラス、葉、水、半ブロック、階段は対象外。 |
| 溺れ | 目の高さが水なら毎tick空気を1消費する。0に達した後、空気0で水中にいる時間が20 tick経つごとに2ダメージ。水の外では毎tick空気が5戻り、300を上限とする。 |
| 奈落 | 足元が `MIN_Y - 64`（−128）を下回ると、10 tickごとに4ダメージ。 |
| 自然回復 | 体力が最大未満の状態が80 tick続くごとに1回復。⑤-2で空腹による回復に置き換える。 |

足元の当たり判定の真下0.001ブロックに、予測と同じブロック形状で支えがあるかを調べる。空中では受理位置の最高のyを落下の起点として保持し、着地または足元が水に入ったときに消す。地面を離れるときは、最後に地面にいた高さを起点にする。テレポートとリスポーンでは移動先のyを起点にする。移動報告が同じtickに複数届く場合も、各受理位置で最高点と着地を記録する。落下、窒息、溺れ、奈落、回復の順で処理し、体力が尽きた時点で処理を止める。

サバイバルのクライアント予測では飛行切替を無効にする。サーバーは地上から1.5ブロックを超える上昇と、空中で20 tick経っても有効な降下がないまま進む移動報告を拒否する。移動後に地面に立っていて、上昇が段差の高さ（物理の `STEP_HEIGHT`）以内なら、落下中の段差への着地として受け付ける。降下判定の最小差は0.05ブロック。通常の通信は引き続きクライアントの座標報告に基づき、未報告時の移動はサーバーで補間しない。ホストが許可したテレポートは従来どおり使用できる。

この移動検証は、水の浮力や泳ぎがまだ物理に無いことを前提にしている。⑥で水の動きを追加するときに、水中での上昇と滞空を許すようサーバー側の判定を更新する。

## 死亡とリスポーン

体力が0になったら、所持品36枠、2×2、作業台の3×3、カーソルの順で空でない枠を死亡位置へ落とす。速度は `[0, 0.1, 0]`、拾得待ちは40 tick。採掘を中断し、作業台・かまどの画面を閉じる。かまどの入力・燃料・出力はその場に残る。ドロップには既存のアイテムエンティティの規則が適用され、奈落では次のエンティティ更新で消える。

死亡中は移動、採掘、設置、クリック、アイテム投棄、ブロック使用、選択枠変更などの操作を拒否して拒否数を増やす。拾得と体力・空気の更新も停止する。接続済みかつ死亡中に `Respawn` を受け取ると、体力20、空気300、死因なしに戻し、出現地点へ移動して `PlayerCorrect` を送る。

## HUDと死亡画面

サバイバルのホットバー上にハートを10個表示する。体力2でハート1個が満ち、端数の1は半分になる。空気が最大未満になると、残り空気を30で割って切り上げた数だけ泡を表示する。両方のメーターは読み上げ用のラベルと現在値を持つ。体力が減ると、画面の端が約0.3秒赤く光る。

サーバーから死亡状態が届くと、所持品・作業台・かまどの画面を閉じてポインターロックを外し、死因と「リスポーン」ボタンを含む「やられた」画面を開く。ボタンは Enter と Space でも押せる。死亡画面の間はゲームの操作を止め、Esc を押しても画面を維持する。サーバーから生存状態が届いたら死亡画面を閉じ、ポインターロックを取り直す。

## ブラウザーE2E

`tools/e2e.mjs` の `survivalHealth()` は新規の Flat サバイバルで、満タンのハート10個から開始する。開発用テレポートで10ブロック上から落下し、体力13、満タン6個と半分1個のハート、赤い点滅を確認する。地面を掘って拾ったブロックを持ったまま40ブロック上から落下し、死亡画面の死因と着地点のドロップを確認する。「リスポーン」を押した後は、体力20、出現地点への移動、死亡画面の終了とポインターロックの復帰を確認する。

## プロトコル9

- S2C `PlayerStatus`（0x0c）の本体は `health u8, air u16 BE, dead u8, cause u8`。接続したtickの `Welcome` の後と、状態が変わったtickの終わりに1回送る。
- 死因は0がなし、1が落下、2がブロック内での窒息、3が溺れ、4が奈落。死亡フラグは0か1。生存時は体力1〜20かつ死因0、死亡時は体力0かつ死因1〜4。空気は0〜300。
- C2S `Respawn`（0x0c）は本体なし。クライアントWasmは状態を保持し、TSから `core.health`、`core.air`、`core.dead`、`core.deathCause`、`core.encodeRespawn()` を利用できる。

## プレイヤーのデータ

`inventory_data` が返すバージョン4は157バイト。先頭1バイトが版番号4で、所持品とクラフト枠の配置はv3と同じ。末尾に `health u8, air u16 BE, dead u8, cause u8` を追加する。体力・空気・死亡フラグ・死因は `PlayerStatus` と同じ規則で検証する。v1〜v3も受け付け、体力20、空気300、生存、死因なしで復元する。落下の起点と各処理の間隔は接続時に初期化する。枠配置の詳細は [crafting.md](crafting.md#閉じる切断保存) を参照。

シングルプレイはOPFSの `player.dat`、マルチプレイはWorldDOの `inventories` で記録する。WorldDOは切断時に `returnCrafting` を呼び、位置とプレイヤーのデータを覚えてから `disconnect` を呼ぶ。同じWorldDOへの再接続で、死亡中のクライアントも保存した状態から再開する。

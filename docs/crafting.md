# インベントリと 2×2・作業台の 3×3 クラフト

数値とレシピはこのプロジェクトのデータ。アイテム画像は公式パックから取得する。処理は決定論的な Rust コアに置き、クライアントは Inventory を受信して表示する。クリックの先読みはしない。Creative でもコアの操作は同じだが、E は従来のブロック選択画面を開く。Survival では E でインベントリを開き、ポインターロックを解除する。E・Esc・閉じるボタンで CloseInventory を送ってロックを戻す。

## 枠と操作

| 番号 | 用途 |
| --- | --- |
| 0〜8 | ホットバー |
| 9〜35 | 所持品27枠 |
| 36〜39 | 2×2クラフト、左上から行順 |
| 40 | 2×2 の結果、毎回計算し保存しない |
| 41〜49 | 作業台の 3×3、左上から行順 |
| 50 | 作業台の結果、毎回計算し保存しない |

枠へTabでフォーカスし、Enter / Spaceで左操作、メニューキー / Shift+F10で右操作ができる。左操作はclick、右操作はcontextmenuでそれぞれ1回だけ送信し、標準のコンテキストメニューは表示しない。キーボード由来の右操作は常にshiftなし（通常枠では半分を取る）として扱う。shift付きの移動はShift+Enterで行える。マウスの右操作と左操作ではshiftKeyをそのまま使う。

カーソルは独立したスタック。クライアント WASM の表示用配列では従来どおり41番に対応し、追加した作業台9枠は42〜50番に連結する（クリック番号とは異なる）。ClientCore.table はこの9枠、screen は0/1、craftingResult は現在の画面の結果を返す。UI はこの対応で表示し、ボタンの `data-slot` には送信する番号を使う。

作業台を開いていないときは41〜50、開いているときは36〜40を拒否する。51以上は常に拒否する。

| 対象 | 操作 | カーソル・枠の条件 | 結果 |
| --- | --- | --- | --- |
| 通常枠 | 左 | カーソルが空 | 全量を拾う |
| 通常枠 | 右 | カーソルが空 | 半分を切り上げて拾う |
| 通常枠 | 左 | 枠が空または同じアイテム | 上限まで置き、余りはカーソル |
| 通常枠 | 右 | 枠が空または同じアイテム | 空きがあれば1個置く |
| 通常枠 | 左・右 | 異なるアイテム | 入れ替え |
| 結果 | 左・右 | レシピ一致、空または同じカーソルに結果全量が入る | 結果を加え、空でない各材料枠から1個消費 |
| 結果 | 左・右 | 結果全量が入らない | 変更なし |
| 結果 | shift + 左・右 | レシピ一致、所持品へ全量入る | addで挿入し消費、可能な限り繰り返す |
| 0〜8 | shift + 左・右 | 任意 | 9〜35へ移動 |
| 9〜35 | shift + 左・右 | 任意 | 0〜8へ移動 |
| 36〜39 / 41〜49 | shift + 左・右 | 開いている画面の材料枠 | 0〜35へ移動 |

shift移動は対象範囲の同じアイテムを番号順に埋め、その後に空き枠を番号順に使う。入りきらない分は元の枠に残す。shiftではカーソルを変更しない。空枠で拾う操作や上限まで埋まった枠へ置く操作は変更なし。結果取得は材料と出力の両方を一括で変更し、出力の一部だけを作らない。

## レシピの定義と照合

`data/registry/recipes.toml` を `crates/world/build.rs` が読み、ファイル順を維持した `world::recipes::RECIPES` を生成する。

```toml
[[recipes]]
pattern = ["#", "#"]
key = { "#" = "oak_planks" }
result = { item = "stick", count = 4 }

[[recipes]]
ingredients = ["oak_log"]
result = { item = "oak_planks", count = 4 }
```

形ありは1〜3行、各行1〜3文字で同じ幅。空白は空き、他の文字はkeyでアイテム名へ対応付ける。形なしはingredientsの1〜9個のアイテム名。resultのcountは1〜そのアイテムのmax_stack。未知のアイテム、keyにない文字、未使用key、行幅不一致、範囲外の個数、同じ材料配置の重複はビルド時に拒否する。形あり・形なしの混在指定も拒否する。形ありの外周の空白は生成時にも切り詰めて重複検出する。

照合は `sim::inventory::matching_recipe` の1か所。グリッドの幅・高さを引数に取り、2×2・3×3で共有する。空の外周行・列を切り詰めた長方形と形ありpatternを比較する。内側の空きは維持し、左右反転しない。形なしは空でない枠のアイテムIDの多重集合と比較する。スタックの個数は一致判定には使わず、取得時に各材料枠から1個使う。ファイル順で最初に一致したレシピを採用する。グリッドに収まらない形は一致しない。

| 今回の材料 | 形 | 出力 |
| --- | --- | --- |
| oak_log ×1 | 形なし | oak_planks ×4 |
| oak_planks ×2 | 縦2枠 | stick ×4 |
| oak_planks ×4 | 2×2 | crafting_table ×1 |
| oak_planks ×3 + stick ×2 | `###` / ` \| ` / ` \| ` | wooden_pickaxe ×1 |
| oak_planks ×3 + stick ×2 | `##` / `#\|` / ` \|` | wooden_axe ×1 |
| oak_planks ×1 + stick ×2 | `#` / `\|` / `\|` | wooden_shovel ×1 |
| cobblestone + stick | 上の3種と同じ形・個数 | stone_pickaxe / stone_axe / stone_shovel 各1 |

石の道具の材料となる丸石（cobblestone）は、石（stone）を木のつるはしで掘って拾うことで手に入る。

道具の6レシピは高さ3なので2×2では作れない。斧は左右反転しない。銅・鉄の道具はかまどのPRで追加する。build.rs は既存の3×3・空白・key検証をそのまま使用する。

## 閉じる、切断、保存

CloseInventory・切断では、2×2、3×3、カーソルの順にaddで所持品へ戻し、screenをNoneへ戻す。余りはプレイヤー位置にアイテムエンティティとして落とす（初速 `[0, 0.1, 0]`、拾得待ち40ticks）。返却によるインベントリ変更も次の送信対象になる。

inventory_dataはプレイヤーのデータとして、実際の所持品36枠・クラフト4枠・カーソル・作業台9枠と体力・満腹度の状態を保存する。現行バージョン6は258バイトで、下記のv3と同じ枠配置の各枠に耐久値の消耗を足し、末尾に体力・満腹度などの6バイトを続ける。screenは保存しない。返却処理は行わず、所持品・一時枠・エンティティを変更しないため、自動保存中もクラフトを続けられる。満杯で返却できない分も一時枠として保存され、再読み込みで失われない。結果枠は派生値なので保存しない。現行形式の詳細は [保存形式](storage.md#耐久値の保存) を参照。

| 順序 | 保存形式（バージョン3、合計152バイト） |
| --- | --- |
| 1 | バージョン u8（3） |
| 2 | 選択枠 u8（0〜8） |
| 3 | 所持品36枠（0〜35） |
| 4 | クラフト4枠（36〜39、行順） |
| 5 | カーソル1枠 |
| 6 | 作業台9枠（行順、旧v2の後ろへ追加） |

各スタックはitem u16 BE / count u8、空は0 / 0。読み込みは旧バージョン1（110バイト、選択枠と所持品36枠のみ）と2（125バイト、所持品・2×2・カーソル）も受け付け、存在しない枠は空として扱う。全形式で未知のID、不正な個数・選択枠、短いデータ、余分なバイトを拒否する。

connect_atで読み込んだ後、クラフト枠とカーソルを所持品へ返却し、余剰は接続したプレイヤーの位置へ落とす。初速・拾得待ちはCloseInventoryと同じ。再読み込み後はインベントリ画面を閉じた状態で、物は所持品か足元にある。エンティティ自体は保存しないため、保存からの余剰の生成は接続時に行う。マルチプレイのWorldDOは切断時に先にreturnCraftingを呼び、所持品への返却と余剰のドロップを完了してから位置とプレイヤーのデータを覚え、disconnectする。保存した所持品には一時枠の物が残らないため、同じワールドへの再接続で余剰を二重に落とさない。ソケットを削除できたときだけこの後始末を行う。シングルプレイの自動保存は従来どおり状態を変えないinventory_dataを使う。

サーバーABIは7を維持する。C関数の引数・戻り値は変更せず、server_return_crafting / ServerCore.returnCraftingも同じ関数で3×3まで返却する。クライアントにはclient_enc_use_block / client_screenとTSのencodeUseBlockを追加する。

## プロトコル7

既存のパケットIDは維持する。整数は既存と同じビッグエンディアン。

| 方向 / ID | 内容 |
| --- | --- |
| C2S 0x09 ClickSlot | slot u8（0〜50）、button u8（0=左、1=右）、shift u8（0/1） |
| C2S 0x0a CloseInventory | ペイロードなし |
| C2S 0x0b UseBlock | x i32、y i32、z i32 |
| S2C 0x06 Inventory | selected u8、枠数 u8（36）、36枠、クラフト4枠、結果1枠、カーソル1枠、screen u8、作業台9枠 |

各スタックはitem u16 / count u8、空は0 / 0。ID、個数、選択枠、枠数、末尾バイトを検証する。ClickSlotの範囲外のslot・button・shiftはpackets_rejectedを増やし、正しいInventoryを送り直す。入力順でサーバーが処理し、同じtickの変更はInventoryを1回に集約する。screenは0（なし）か1（作業台）のみ受け付ける。resultは開いている画面のグリッドから計算する。

UseBlockは接続済みプレイヤーがscreen=Noneで、対象がcrafting_tableかつ既存のwithin_reach（ブロック中心から半径8）内の場合だけ開く。拒否時はpackets_rejectedを増やしInventoryを再送する。毎tick、パケットと採掘処理の後に対象ブロックと到達範囲を確認し、壊れた・範囲外の場合はCloseInventoryと同じ返却を行う。

## 作業台の画面と確認

設置した作業台に照準を合わせて右クリックすると、Survival・Creative ともに作業台を開く。手が空でも開ける。Shift を押して右クリックすると通常のブロック設置になる。長押しによる連続操作では開く要求を繰り返さない。

サーバーの Inventory で screen=1 を受け取ると「作業台」画面を開き、ポインターロックを解除して入力をクリアする。所持品27枠、ホットバー9枠、3×3材料枠と結果を表示し、2×2は表示しない。枠・アイコン・個数・カーソルの描画とキーボード操作はインベントリ画面と共通（Tab、Enter / Space、メニューキー / Shift+F10）。E・Esc・「閉じる」で CloseInventory を送る。作業台が壊れた場合やサーバーの到達範囲から離れた場合にも、screen=0 の通知に合わせて画面を閉じる。材料とカーソルの返却条件は「閉じる、切断、保存」のとおり。

`tools/e2e.mjs` の survivalCrafting は Terrain seed=2026 の出現地点近くで、従来と同じ条件の木から同じ幹の原木を3本順に掘り、拾う。最初の原木から板4枚を取る既存チェックを維持し、残り2本も板へ変え、DOMの枠ボタンで棒と作業台を作る。作業台をホットバーで選んで地面に置き、getBlock と所持品の更新で設置を確認する。右クリックで画面を開き、上段の板3枚と中央列の棒2本から wooden_pickaxe を作って所持品へ入れ、閉じた後も残ることを確かめる。アイテム注入はせず、各操作後は waitForFunction で Inventory による枠表示の更新を待つ。

かまどと銅・鉄の道具は後続PRで追加する。

## かまど（サーバー・プロトコル8）

`furnace` は向きのない1状態。丸石8個の `### / # # / ###` で作る。
銅・鉄のつるはし、斧、シャベルは木・石と同じ形で、材料を各インゴットにする。
石炭、銅インゴット、鉄インゴットはブロックではない。

`smelting.toml` は入力と出力のアイテム名を指定し、銅鉱石→銅インゴット、鉄鉱石→鉄インゴット、砂→ガラス、丸石→石を各1個ずつ精錬する。未知の名前と入力の重複はビルドエラー。
1回は `world::smelting::SMELT_TICKS = 160` tick。`items.toml` の任意の `fuel` は正の u32 整数。石炭1600、原木・板・作業台320、棒80 tick。

読み込まれたかまどは `BTreeMap<[i32;3], Furnace>` に保持し、誰も開いていなくても、プレイヤーの読み込みを保つ範囲内のチャンクだけ座標順に進める。入力が精錬可能で出力に1個追加できるとき、燃えていなければ燃料を1個消費する。燃焼残りを1減らし、精錬可能なら進みを1増やす。160で入力を1個消費し出力を1個増やして進みを0にする。出力が満杯・異種、入力が不適合、または燃焼していないtickは進みを0にする。最後の燃焼tickでも進みは増えるが、次tickに燃料を補充できなければ0へ戻る。棒1個では完了しない。
状態変更はチャンクをdirtyにする。保存済みで遠いチャンクはかまどを進める前に読み込み解除し、状態もメモリから消す。再読込で復元する。読み込まれたかまどの件数・座標・全状態はstate_hashに含む。設置時は空。破壊時は両モードとも入力・燃料・出力をその位置に落とす。

`Screen::Furnace { pos }` のときだけ51=入力、52=燃料、53=出力を使い、36〜50は拒否する。入力には何でも置ける。燃料枠にはfuelのある物だけ置ける。出力は取り出しだけで、右クリックは半分（切上げ）、shiftは所持品へ移す。所持品からのshiftは精錬可能なら入力、次に燃料なら燃料、それ以外は従来のホットバー・所持品間移動。優先先が満杯ならその場に残す。閉じてもかまどの中身は残り、カーソルは既存の返却処理で所持品へ戻す。
UseBlockの開く条件、毎tickとクリック前の存在・距離確認、拒否時のInventory再送は作業台と同じ。同じかまどを複数人が開け、変更は全閲覧者へ同tickのInventoryで送る。

プロトコル8ではClickSlotを0〜53へ拡張する。Inventoryはプロトコル7の末尾（作業台9枠）の後に、かまど3枠（各item u16/count u8）、燃焼残りu16、燃焼全体u16、進みu16を追加する（常に15バイト）。screenは0=なし、1=作業台、2=かまど。開いていない場合は追加3枠が空で時間も0。燃焼残り・全体は0〜1600へクランプしたtick数を送る。進みは0〜159。整数はビッグエンディアン。WASMクライアントの表示配列は既存0〜50を維持し51〜53にかまど3枠を追加する（クリック番号とはクラフト・カーソル部分の配置が異なる）。時間はclient_furnace_time(0/1/2)で残り・全体・進みを読む。サーバーC ABIは引き続き7。

### かまどの画面とE2E

Shiftなしの右クリックで `UseBlock` を送り、サーバーの screen=2 を受け取ると「かまど」（`#furnace-screen`）を開く。Shiftを押している場合は設置操作になる。インベントリ・作業台と共通の画面部品を使い、所持品27枠、ホットバー9枠、その下に入力51・燃料52を縦に並べ、矢印の右に出力53を置く。燃焼ゲージは残り / 全体、精錬ゲージは進み / 160 tickを示し、Inventoryの受信ごとに更新する。両方に `role="progressbar"` と `aria-valuenow` / `aria-valuemax` を付ける。燃料がない場合は燃焼0 / 0で空表示になる。

E（設定で変更可能）・Esc・「閉じる」で閉じる要求を送る。枠はTabでフォーカスし、Enter / Spaceで左クリック相当、Shift併用でまとめて移動、コンテキストメニューキー / Shift+F10で右クリック相当の操作を行う（Shift+F10自体はまとめて移動にしない）。枠の規則はサーバーに任せ、クライアントで中身を先に変えない。表示はサーバーのscreenとローカルのclosePendingで決める。閉じた直後の古いInventoryでは開き直さず、新しいUseBlockではclosePendingを解除するため、閉じる・開くが同じtickでも再表示できる。サーバーが距離などを理由に閉じた場合も画面を閉じる。

`tools/e2e.mjs` の `furnaceSmelting()` はサバイバルのクラフト確認後に実行する。クリエイティブのFlatワールドでブロック選択画面からfurnace・iron_ore・coalをホットバーへ入れる。地面へ右クリックで設置し、getBlockで確認してから右クリックで画面とscreen=2を確認する。DOMの枠ボタンで鉄鉱石を入力、石炭を燃料へ移し、燃焼ゲージの減少と精錬ゲージの進行を待つ。160 tick（通常約8秒）の精錬で出力にiron_ingotが出るまでwaitForFunctionで待つ（上限20秒）。出力をShiftクリックで所持品へ移し、「閉じる」でscreen=0になることを確認する。新しいcheckはすべて `furnace:` で始まる。

## チェスト（サーバー・プロトコル31）

チェストは不透明な1マスの立方体で、状態IDは85、アイテムIDは83。向きは持たず、正面は北の `chest_front`、上下は `chest_top`、残りの側面は `chest_side`。適正道具は斧で最低ティア0、採掘の基準時間は50 tick。燃料にすると320 tick燃える。作業台の3×3でオークの板8個を輪（`###`、`# #`、`###`）に並べるとチェスト1個ができる。2×2では作れない。

Shiftなしの右クリックで `UseBlock` を送り、Shiftを押している場合は設置操作になる。開く条件、毎tickとクリック前の存在・距離確認、拒否時のInventory再送は作業台・かまどと同じ。設置直後や保存データに記載がない位置のチェストは空。隣に置いても各チェストが独立した27枠を持つ。同じチェストを複数人が開け、変更は全閲覧者へ同tickのInventoryで送る。

`Screen::Chest { pos }` のときは所持品・ホットバーの0〜35と、左上から行ごとに並ぶチェストの54〜80を使う。36〜53は拒否し、54〜80はほかの画面では拒否する。チェストの枠には何でも置ける。左クリックで拾う・置く・入れ替える、右クリックで半分（切上げ）を拾うか1個置く。Shiftクリックは所持品・ホットバーとチェストの間で移動する。移動先では同じアイテムと耐久値の山に足してから空き枠を使う。チェストへは54から、所持品へは0から順に埋め、入りきらない分は元の枠に残す。スタックを移動しても `damage` を引き継ぐ。

閉じてもチェストの中身は残り、カーソルは既存の返却処理で所持品へ戻す。破壊や爆発では両モードとも中身をその位置に落とす。プレイヤーが死亡したときは持ち物だけを落とし、チェストの中身は残る。中身が変わったチャンクはdirtyになり、読み込み解除時にチェストの状態もメモリから取り除く。[保存形式](storage.md#チャンク本体のチェスト末尾)

プロトコル31ではClickSlotを0〜80へ拡張する。Inventoryではかまどの時間の後に、チェスト27枠を追加する（常に135バイト）。各枠はitem u16、count u8、damage u16の順で、整数はビッグエンディアン。screenは0=なし、1=作業台、2=かまど、3=チェスト。screenが3以外の場合は27枠とも空で送り、中身があれば受信時に拒否する。WASMクライアントの表示配列は既存の0〜53を維持し、54〜80にチェスト27枠を追加する。カーソルは引き続き表示配列の41で読む。

### チェストの画面と E2E

サーバーの screen=3 を受け取ると「チェスト」（`#chest-screen`）を開く。上からチェスト27枠（9列×3行、左上から54〜80）、所持品27枠、ホットバー9枠を並べる。枠のクリック・Shiftクリック・右クリック、カーソルと耐久値の表示にはかまどと共通の部品を使う。中身はサーバーからのInventoryで更新する。E（設定で変更可能）・Esc・「閉じる」で閉じる要求を送り、サーバーが閉じた場合も画面を閉じる。

`tools/e2e.mjs` の `chestStorage()` は `furnaceSmelting()` の直後に実行する。クリエイティブのFlatワールドでブロック選択画面からchestとiron_oreをホットバーへ入れる。地面に右クリックで設置し、getBlockで確認してから右クリックで画面とscreen=3を確認する。DOMの枠ボタンで鉄鉱石を54へ移し、Shiftクリックで所持品へ戻す。チェストに入れ直してから「閉じる」でscreen=0になることを確認し、再び開いて54に鉄鉱石が残っていることとページエラーがないことを確認する。枠の更新はwaitForFunctionで待つ。checkはすべて `chest:` で始まる。

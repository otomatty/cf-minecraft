# インベントリ画面と 2×2 クラフト

数値、レシピ、絵は本プロジェクト独自のデータ。処理は決定論的な Rust コアに置き、クライアントは Inventory を受信して表示する。クリックの先読みはしない。Creative でもコアの操作は同じだが、E は従来のブロック選択画面を開く。Survival では E でインベントリを開き、ポインターロックを解除する。E・Esc・閉じるボタンで CloseInventory を送ってロックを戻す。

## 枠と操作

| 番号 | 用途 |
| --- | --- |
| 0〜8 | ホットバー |
| 9〜35 | 所持品27枠 |
| 36〜39 | 2×2クラフト、左上から行順 |
| 40 | 結果、毎回計算し保存しない |

カーソルは独立したスタック。クライアントの表示用配列では41番に対応するが、クリックできる番号ではない。

| 対象 | 操作 | カーソル・枠の条件 | 結果 |
| --- | --- | --- | --- |
| 通常枠 | 左 | カーソルが空 | 全量を拾う |
| 通常枠 | 右 | カーソルが空 | 半分を切り上げて拾う |
| 通常枠 | 左 | 枠が空または同じアイテム | 上限まで置き、余りはカーソル |
| 通常枠 | 右 | 枠が空または同じアイテム | 空きがあれば1個置く |
| 通常枠 | 左・右 | 異なるアイテム | 入れ替え |
| 結果 | 左・右 | レシピ一致、空または同じカーソルに結果全量が入る | 結果を加え、空でない各材料枠から1個消費 |
| 結果 | 左・右 | 結果全量が入らない | 変更なし |
| 結果 | shift + 左・右 | レシピ一致、所持品へ全量入る | addで挿入し消費、可能な限り繰り返す |
| 0〜8 | shift + 左・右 | 任意 | 9〜35へ移動 |
| 9〜35 | shift + 左・右 | 任意 | 0〜8へ移動 |
| 36〜39 | shift + 左・右 | 任意 | 0〜35へ移動 |

shift移動は対象範囲の同じアイテムを番号順に埋め、その後に空き枠を番号順に使う。入りきらない分は元の枠に残す。shiftではカーソルを変更しない。空枠で拾う操作や上限まで埋まった枠へ置く操作は変更なし。結果取得は材料と出力の両方を一括で変更し、出力の一部だけを作らない。

## レシピの定義と照合

`data/registry/recipes.toml` を `crates/world/build.rs` が読み、ファイル順を維持した `world::recipes::RECIPES` を生成する。

```toml
[[recipes]]
pattern = ["#", "#"]
key = { "#" = "oak_planks" }
result = { item = "stick", count = 4 }

[[recipes]]
ingredients = ["oak_log"]
result = { item = "oak_planks", count = 4 }
```

形ありは1〜3行、各行1〜3文字で同じ幅。空白は空き、他の文字はkeyでアイテム名へ対応付ける。形なしはingredientsの1〜9個のアイテム名。resultのcountは1〜そのアイテムのmax_stack。未知のアイテム、keyにない文字、未使用key、行幅不一致、範囲外の個数、同じ材料配置の重複はビルド時に拒否する。形あり・形なしの混在指定も拒否する。形ありの外周の空白は生成時にも切り詰めて重複検出する。

照合は `sim::inventory::matching_recipe` の1か所。グリッドの幅・高さを引数に取り、将来の3×3にも使える。空の外周行・列を切り詰めた長方形と形ありpatternを比較する。内側の空きは維持し、左右反転しない。形なしは空でない枠のアイテムIDの多重集合と比較する。スタックの個数は一致判定には使わず、取得時に各材料枠から1個使う。ファイル順で最初に一致したレシピを採用する。グリッドに収まらない形は一致しない。

| 今回の材料 | 形 | 出力 |
| --- | --- | --- |
| oak_log ×1 | 形なし | oak_planks ×4 |
| oak_planks ×2 | 縦2枠 | stick ×4 |
| oak_planks ×4 | 2×2 | crafting_table ×1 |

## 閉じる、切断、保存

CloseInventory・切断では、クラフト枠36〜39、カーソルの順にaddで所持品へ戻す。余りはプレイヤー位置にアイテムエンティティとして落とす（初速 `[0, 0.1, 0]`、拾得待ち40ticks）。返却によるインベントリ変更も次の送信対象になる。

inventory_dataは所持品を複製し、その複製にだけクラフト枠とカーソルを同じ順で返却して保存用バイト列を作る。実際の所持品・クラフト枠・カーソル・エンティティは変更しないため、自動保存中もクラフトを続けられる。複製の所持品に入りきらない分は保存されず、エンティティにもならない（実際の一時枠には残る）。

保存形式はバージョン1の既存36枠と選択枠のまま。クラフト枠・結果・カーソルは保存しない。切断時も保存を行うホストは、切断前にinventory_dataを取得する。

## プロトコル6

既存のパケットIDは維持する。整数は既存と同じビッグエンディアン。

| 方向 / ID | 内容 |
| --- | --- |
| C2S 0x09 ClickSlot | slot u8（0〜40）、button u8（0=左、1=右）、shift u8（0/1） |
| C2S 0x0a CloseInventory | ペイロードなし |
| S2C 0x06 Inventory | selected u8、枠数 u8（36）、36枠、クラフト4枠、結果1枠、カーソル1枠 |

各スタックはitem u16 / count u8、空は0 / 0。ID、個数、選択枠、枠数、末尾バイトを検証する。ClickSlotの範囲外のslot・button・shiftはpackets_rejectedを増やし、正しいInventoryを送り直す。入力順でサーバーが処理し、同じtickの変更はInventoryを1回に集約する。クライアントWASMは36枠に追加6枠を連結し、TypeScriptのinventoryDisplayが表示順へ並べる。

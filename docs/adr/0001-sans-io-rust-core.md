# ADR 0001: ゲームロジックは I/O を持たない Rust コアに置く

状態: 採用（2026-11-10）

## 背景

Java版の仕様を再現するには、32/64ビット整数のオーバーフロー、`float` と `double` の使い分け、乱数列をビット単位で合わせる必要があります。また、シングルプレイ（ブラウザ内）とマルチプレイ（Durable Object）で同じ挙動を保証しなければなりません。

## 決定

- シミュレーションは Rust で書き、WebAssembly とネイティブの両方にビルドします。
- コアはソケット、時計、ストレージ、スレッドに触れません。ホストが次の順で駆動します。
  1. 受信パケットを渡す（次の tick の先頭で、到着順に適用）
  2. `tick()` を呼ぶ（ゲーム時間でちょうど 1/20 秒）
  3. 送信パケット、ストレージへの読込要求、保存すべきチャンクを取り出す
- WASM モジュールは import を持ちません。ホストとの境界はバイト列だけです。
- コア内では順序付きコレクションのみを使い、libm に依存する関数を呼びません。

## 結果

- 同じ入力から同じ状態になることを、ホストをまたいでハッシュで検証できます（`tools/determinism.mjs`）。
- ストレージが同期（SQLite）でも非同期（OPFS）でも、コアは同じ要求・応答の形で扱えます。
- ホスト側のコードは薄く保てます。Durable Object は約260行、ブラウザの Worker は約190行です。
- 代償として、三角関数や対数などは自前の移植が必要になります（M1 以降）。
- JavaScript から WASM メモリへのコピーが境界ごとに発生します。M0 の計測では問題になっていません。

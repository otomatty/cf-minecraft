# ADR 0002: Better Auth と D1 でワールドへの参加を管理する

状態: 採用（2026-11-12）

## 背景

本番のワールドを誰でも作成・操作できる状態では、保存領域と実行時間を制御できません。利用者を識別し、招待した人だけが参加できる仕組みが必要です。ログインとセッション管理を独自に実装する負担も避けたいです。一方、ローカルの開発と計測ツールは認証なしで動かし続ける必要があります。

## 決定

- 認証は Better Auth を使います。最初は Google OAuth のみとし、メールとパスワードによる認証は有効にしません。パスワードの保管と再設定の運用を持たずに、検証済みのメールアドレスを使えます。
- セッションとアカウント、ワールド、メンバーは D1 に保存します。Better Auth のスキーマは採用した版の `getMigrations` の出力に合わせます。マイグレーションは Worker の公開前に適用します。
- 招待は小文字に正規化したメールアドレスで管理します。未登録の人も招待できます。参加には検証済みのメールアドレスが必要です。
- 作成できる人は `WORLD_CREATORS` のカンマ区切りのメールアドレスで指定します。1人5ワールド、1ワールド64メンバーを上限にして、利用量を制御します。作成者は operator とし、オーナーの削除・降格は禁止します。
- 参加はメンバーに限ります。メンバーの一覧・追加・役割更新・削除と metrics の閲覧は、そのワールドの operator に限ります。認証・登録・権限の確認は Durable Object を取得する前に行います。
- Turnstile は Google ログインの開始とワールド作成で検証します。自動化による認証・作成の濫用を抑えます。変更系 API では同一オリジンも確認します。
- レート制限は `/api/*` と `/ws/*` に IP ごと120回/60秒、認証操作（`GET /api/auth/get-session` を除く）と運用者トークンの照合失敗に IP ごと20回/60秒、ワールドの POST/DELETE にユーザーごと30回/60秒を適用します。開発専用 `/api/debug` は対象外です。上限を超えたら429を返します。
- `ACCESS_TOKEN` は運用者トークンとして残します。`Authorization: Bearer` の場合だけ受け付け、クッキーには使いません。tick-probe が任意の正しい名前のワールドに接続し、metrics を取得するためのものです。定数時間で比較し、照合失敗には認証のレート制限を適用します。
- 本番で認証に必要な secret が欠けている場合は503を返し、認証が要るルートを閉じます。`WORLD_CREATORS` が空なら作成不可、`ACCESS_TOKEN` が空なら運用者トークンは無効とします。
- 開発時（`DEBUG=1`）は認証とレート制限をかけず、今までどおり開いたままにします。ローカル開発と CI の計測・決定論チェックを継続できます。

### 接続中の再検証（issue #39）

ログアウトとメンバー削除では引き続き即時に `WorldDO.revoke(userId)` を呼びます。その呼び出しや所属ワールド検索に失敗しても接続が残り続けないよう、案 B（接続中の再検証）を採用します。案 A（失敗を記録して後で revoke）と異なり、失敗の種類によらず、セッションの期限切れやメンバー資格の喪失も検出できるためです。

Worker は Better Auth の `session.id` を内部ヘッダー `X-MC-Session` で DO に渡します。トークンは渡さず、外から来た同名のヘッダーは必ず削除します。DO は接続ごとにユーザー ID とセッション ID を保持し、tick ループから60秒間隔（定数 `ACCESS_RECHECK_MS`）で D1 に問い合わせます。全接続のセッション ID を `IN (...)` でまとめた1回の SQL で、セッションの存在・所有ユーザー・有効期限、検証済みメールとワールドのメンバー資格を確かめます。オーナーにも入場時と同じメンバー登録を要求します。認証なしの開発接続と運用者トークンの接続は対象外です。

無効な接続は `ACCESS_REVOKED`（4001）で閉じ、revoke と同様にソケット・ユーザー・セッション・パケット数を削除し、ゲーム側も切断します。クライアントは自動再接続しません。問い合わせは非同期で tick を止めず、同時には1つだけ実行します。D1 障害時は全員を切断せずログを残し、次の60秒間隔で再試行します。そのため切断までの時間は通常次の検証までですが、D1 障害中は延びます。

## 結果

- 利用者はアカウントページでログインし、参加できるワールドと招待を管理できます。ゲームへの入場トークン入力は不要になります。
- 未認証や未招待の接続で Durable Object が作られることを防げます。運用計測はブラウザのログインから独立して実行できます。
- 代償として、D1、Google OAuth、Turnstile の設定と secret の管理が必要になります。ログインには外部サービスへの接続が必要です。
- Google 以外の認証方式や公開参加のワールドは、必要になった時点で検討します。

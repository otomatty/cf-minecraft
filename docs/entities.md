# エンティティ、ドロップと拾得

この文書は落ちているアイテムを扱う。プロトコル13で追加した牛は、アイテムと ID 空間および `EntityRemove` を共有する。[Mob と牛](mobs.md)

ワールドが `BTreeMap` でエンティティを所有し、ID昇順で移動・拾得・通知を処理する。種類は拡張可能な enum。位置は箱の底面中心、速度はブロック/tick。時刻・環境に依存せず、ドロップの乱数はワールドの seed と次のエンティティIDから `JavaRandom` を作る。浮動小数点は基本演算、floor、sqrt で計算する。

| 基盤 | 値 |
| --- | --- |
| ID | u32、開始1、単調増加、再利用しない |
| アイテムの種類番号 | 0 |
| 箱の幅・高さ | 0.25 / 0.25 |
| tick 周波数 | 20 Hz |
| アイテムエンティティ上限 | 1024 |
| 寿命 | 経過6000 tick（5分）で消去 |
| 奈落の消去条件 | y < MIN_Y − 64 |

状態は種類、位置、速度、アイテムID、個数、経過tick、拾得待ちtick、接地フラグ。状態ハッシュは次のIDと件数、およびID順に全フィールドを含める。チャンクがメモリにない間は移動・年齢・拾得待ちを進めず、合体と拾得も行わない。メモリからチャンクを読み込み解除すると、そのチャンクのエンティティを消す。**エンティティは保存しない。保存は後のPRで実装する。**

パケット適用とチャンク送信のあと、重力、衝突解決、減衰を行う。衝突はプレイヤーと同じ `physics::resolve` とブロック形状を使い、止められた軸の速度をゼロにする。下向きの移動が止められると接地する。箱が固体に重なる間は、通常の衝突解決をせず上へ押し出す。ワールドの上下限の外は空気として落下できる。

| 運動・合体 | 値 |
| --- | --- |
| 重力 | 毎tick、y速度から0.04を引く |
| y速度の減衰 | 0.98倍 |
| 横速度の減衰（接地 / 空中） | 0.6 / 0.98倍 |
| 埋まり時の上昇 | 毎tick 0.1 |
| 合体の間隔 | ワールド時刻が10 tickの倍数になるtick |
| 合体の距離 | 各軸の差が0.5以下 |
| 合体候補 | 同じアイテムの1ブロック格子と隣接格子。満杯スタックは比較しない |
| 合体の比較数上限 | 1回4096組。小さいID順に比較し、上限でその回を打ち切る |
| 合体の個数 | 合計がアイテムのmax_stack以下のときだけ |

合体は同じアイテムを小さいIDへまとめる。経過tickと拾得待ちは大きい方を引き継ぎ、寿命の延長や拾得待ちの短縮を防ぐ。上限を超える生成では最小IDのものから消す。

Survivalのブロック破壊は対応アイテムをドロップする。Creativeの破壊はドロップしない。`DropItem` は両モードで選択枠から取り出す。空の枠は何もせず拒否数も増やさない。参加前の操作と非有限の方向は拒否する。

| 生成・拾得 | 値 |
| --- | --- |
| 破壊時の個数 | 1 |
| 破壊時の位置 | (x + 0.5, y + 0.25, z + 0.5) |
| 破壊時の横速度 | 各軸 −0.05〜0.05 |
| 破壊時のy速度 | 0.1 |
| 破壊時の拾得待ち | 10 tick |
| 捨てる個数 | 1 |
| 捨てる位置 | プレイヤーの足元からy + 1.3 |
| 方向の正規化 | 長さが1を超えれば長さで割る。長さ0はゼロベクトル |
| 捨てる速度 | dir × 0.3、さらにy + 0.1 |
| 捨てるときの拾得待ち | 40 tick |
| 拾得範囲の拡張 | プレイヤー箱を横の両側に1.0、縦の両側に0.5 |
| 拾得可能な待ち残り | 0 tick |
| 初期キー | Q（KeyQ） |

生成したtickも移動と待ち時間の減算を行う。毎tick、参加済みプレイヤーをクライアントID順に調べ、拡張した箱とアイテムの箱が重なれば `Inventory::add` する。入った分だけ減らし、残数がなくなれば消す。満杯なら残る。変化したインベントリは既存の集約方式で本人に送る。

## プロトコルとクライアント

既存のパケット番号は変更しない。複数バイト値はビッグエンディアン。新パケットは末尾バイト、ID、種類、アイテムID、個数、有限座標を検証する。Count単体はアイテムIDを持たないためワイヤ形式の上限を検証し、ミラーで該当アイテムの上限も検証する。

| 方向 | 番号 | 内容 |
| --- | --- | --- |
| 共通 | バージョン4 | 以前は3 |
| C2S | 0x06 | DropItem: dir f32 × 3 |
| S2C | 0x07 | EntitySpawn: id u32, kind u8（0のみ）, item u16, count u8, x/y/z f64 |
| S2C | 0x08 | EntityMove: id u32, x/y/z f64 |
| S2C | 0x09 | EntityCount: id u32, count u8 |
| S2C | 0x0a | EntityRemove: id u32 |
| 個数 | 1〜max_stack | Count単体は1〜64 |
| ID | 1〜u32上限 | 0は拒否 |

クライアントごとに最後に見せたID・位置・個数を保持する。tick末尾で、そのクライアントの `sent` にチャンクがあるものだけを対象とし、新規はSpawn、対象外はRemove、既存の位置差分はMove、個数差分はCount。同じIDへの同じ種類の通知はtick内で重複しない。Spawn時はMove/Countを重ねない。チャンクのUnload時のエンティティ消去は**サーバーが同じtick末尾に送るRemove**で行う。再接続時はミラーを空にする。

WASMはID順の一覧（ID・アイテム・個数・現在と以前の位置）とクライアントワールドの空光・ブロック光を公開する。Moveで現在位置を以前位置にコピーする。TypeScriptは受信からの経過時間で補間し、カメラとの差を倍精度で計算してからGPUへ渡す。小立方体は専用パイプラインで描き、地形と同じライトマップ・面の明るさ・霧を使う。回転と上下動は描画だけでコアを変更しない。F3と `window.__mc.stats().entities` で確認できる。

| 描画 | 値 |
| --- | --- |
| 立方体の一辺 | 0.25 |
| 補間区間 | 50 ms、範囲外は端点に固定 |
| 回転角 | 経過ms / 2000（rad） |
| 上下動 | 0.04 + sin(経過ms / 500) × 0.03 |

## モブの描画アセット

ブタ、ウシ、ニワトリ、ゾンビ、スケルトン、クリーパーの通常の成体を用意した。家畜は温帯の姿に合わせた。体格、各部位の比率、顔や模様の特徴を統合版と照合し、スキンを独自に描いている。参照した版はブロックと同じ [Bedrock Samples v1.26.60.5](https://github.com/Mojang/bedrock-samples/releases/tag/v1.26.60.5)。各モブの通常モデルとバリエーションの対応は [公式のエンティティ定義](https://github.com/Mojang/bedrock-samples/tree/v1.26.60.5/resource_pack/entity) にある。

ゲーム中のウシ、ブタ、ニワトリはこのモデルとスキンで描画する。ヒツジも同じカタログから既存の毛と顔の模様を使う。ゾンビ、スケルトン、クリーパーの生成・行動は今後の実装になる。種類を追加するときは、通信で使う `MobKind` と `minecraft:pig` などの識別子を明示的に対応付け、[カタログ](../apps/web/src/client/mobs/catalog.ts) のアセットを使う。

```ts
import { mobAssets } from "./mobs/catalog.ts";

const pig = mobAssets.get("minecraft:pig")!;
const { width, height } = pig.texture;
const rgba = pig.texture.pixels(); // 初回のテクスチャ転送時に取得し、同種の個体で共有する
```

- `bones` は親から子の順。各箱の `origin` と関節の `pivot` は、ともにモデル全体を基準にした座標。足元が Y=0、正面が −Z。モデルの基準は 1 ブロックあたり 16 単位。ゲーム内のウシ・ブタ・ニワトリは足元を固定し、体の比率を保ったまま、モデルの高さを攻撃の当たり判定に合わせる。
- `uv` はスキン左上を原点とする統合版のボックス UV。スキンは行順の RGBA8 で、最近傍サンプリングとアルファテストを使う。スケルトンの胴体は両面を描き、肋骨の隙間から奥の背骨が見えるようにする。[ボーンと UV の仕様](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/visualreference/geometry.v1.12.0?view=minecraft-bedrock-stable)
- ゾンビの初期姿勢は素手で両腕を前へ伸ばした状態。スケルトンは右腕を18度前に傾けて弓を携える。`rightItem` の子ボーンの `itemSprite.texture` を `itemTexture()` で引き、絵の `grip` をボーンの支点に合わせる。スプライトはボーンのローカル空間で横が +Z、下が −Y。1画素がモデルの1単位に対応し、不透明な画素を X 方向に1単位の厚みで描く。[ゾンビの腕の姿勢](https://github.com/Mojang/bedrock-samples/blob/v1.26.60.5/resource_pack/animations/zombie.animation.json)・[スケルトンの初期装備](https://github.com/Mojang/bedrock-samples/blob/v1.26.60.5/behavior_pack/loot_tables/entities/skeleton_gear.json)
- 歩行時は `walkPitch[bone.name] ?? 0` に `Math.sin(2 * Math.PI * phase)` を掛け、ボーンの初期 X 回転（度）に足す。`phase` の 0〜1 が一歩行周期。停止中は初期姿勢を使う。これで四足は対角の脚、二足は左右の脚が交互に動く。

## スケルトンの矢(⑦-3b)

矢はサーバーの一時エンティティで、アイテムや Mob と同じ ID 採番を使い、ID 順に更新する。発射の次の tick から、速度を足して移動し、速度に 0.99 を掛けてから Y 速度を 0.05 減らす。

移動の線分で最初に交わる衝突形状またはプレイヤーの当たり判定を採用する。同距離ならブロックを優先し、プレイヤー同士なら ID の小さい方を選ぶ。生存中のサバイバルプレイヤーに当たると 3 ダメージを与えて消える。クリエイティブのプレイヤーと Mob は通り抜ける。ブロックに当たると衝突位置に留まり、描画用に衝突時の向きを保持する。

ブロックに刺さってから 100 tick、または発射から 200 tick で消える。未読み込みのチャンクに入った場合や `health::VOID_Y` を下回った場合も消える。刺さった矢は拾えない。矢の保存は行わず、矢が存在する間は状態ハッシュに件数と ID 順の位置・速度・経過 tick・刺さった状態を加える。

プロトコル 19 の `ArrowSpawn`（`0x10`）と `ArrowMove`（`0x11`）は ID（u32）、位置 X/Y/Z（f64）、速度 X/Y/Z（f64）の順。視界から外れた場合と消滅時は共通の `EntityRemove` を送る。クライアントは位置を補間し、アイテムの矢の絵を速度方向に沿う板に描く。

プロトコル 23 で `ArrowSpawn` の末尾に `fresh`（u8、0 または 1）を追加した。発射した tick に同期する矢は 1 で、同じ tick にブロックに刺さった矢も含む。発射より後の tick に視界に入るか再接続で受け取る既存の矢は、飛行中でも刺さっていても 0。`ArrowMove` の形式は従来どおり。

## 落ちているアイテムの保存（⑧-1）

⑧-1 から、落ちているアイテムは足元のチャンクと一緒に保存する。個数、位置、速度、年齢、拾得待ちが復元され、消滅と拾得のカウントを再開する。チャンクを読み込み解除するときは書き出した後にメモリから取り除く。矢は引き続き一時的なエンティティとして扱う。 [チャンク本体のエンティティ末尾](storage.md#チャンク本体のエンティティ末尾⑧-1)

プロトコル 24 では、発言・参加・退出をチャットパケットで同期する。詳細は [チャット](chat.md) を参照。

プロトコル 25 では、ゾンビの近接攻撃による押し返しと Mob の燃焼状態を同期する。詳細は [押し返しと燃えている見た目](mobs.md#プロトコル-25) を参照。

プロトコル 26 では、爆心を `Explosion` で同期する。詳細は [爆発の仕上げ](mobs.md#プロトコル-26) を参照。

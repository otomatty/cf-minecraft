# 水とバケツ

水源は `water`（状態 ID 13）。`flowing_water` は `level=1` から `level=7` の順に ID 62〜68 を使い、上から落ちる `level=falling` は ID 69。いずれも衝突判定のない半透明ブロックで、明るさを 1 段階吸収する。水源と流れる水の両方が落下と空気の判定、草の広がり、耕地の水分に影響する。流れる水に対応するアイテムはなく、中クリックでも選択できない。

## スケジュール tick

プレイヤー操作や自然の変化でブロックが変わると、その位置自身と面で隣り合う 6 マスを調べ、変更後に水がある読み込み済みの位置だけを 5 tick 後に予約する。隣が空けば水側の予定で流れ込み、水源を取り除けば隣の流れる水が状態を計算し直す。地形の生成や読み込み自体では予約を作らない。生成された海や湖は、隣のブロックの変化で予約されてから動く。

サーバーはランダム tick の直後、時刻が来た予定を `(game_time, [x, y, z])` の昇順で処理する。1 つの位置に予定は 1 件まで。隣のブロックが変わって予約が重なった場合は早い時刻を残す。ブロックが変わった位置自身の古い予定は取り除き、そこが水なら変更から 5 tick 後に入れ直す。プレイヤーの表示距離に読み込み解除の余裕 2 チャンクを加えた範囲が対象。範囲外の予定は保持する。面で隣り合う建築範囲内の位置に未読み込みのチャンクが 1 つでもあれば、その予定も保持する。範囲内に入り、必要なチャンクがそろえば、期限を過ぎた予定も実行する。同じ処理中に状態が変わったマスは新しい予定を待つ。

チャンクを保存するときは、かまどのデータに続けて件数を varint で書く。各件はチャンク内の x（u8）、高さ y（i32 BE）、チャンク内の z（u8）、残り tick（u16 BE）の順。残り tick は 0〜65535 に収め、読み込み時の `game_time` に足して予定を復元する。旧データで同じ位置に複数の予定があれば、最も早い時刻を使う。読み込み解除時は保存済みのチャンクの予定をメモリから除く。予約を追加するとチャンクを保存対象にし、実行時はブロックが変わった場合に保存対象にする。保存データに残った実行済みの予定を読み込み後に再実行しても、同じ判定を繰り返すだけで結果は変わらない。[チャンクの保存形式](storage.md#チャンク本体のスケジュール-tick-末尾)

## 流れ方

1. 水源は広がる。空気の予定は何も変更しない。流れる水は、真上が水なら `falling` になる。真上に水がなく、水平に接する水源が 2 つ以上あって真下が固体（`info.solid`）か水源なら、新たな水源になる。
2. それ以外の流れる水は、水平に水源か `falling` があれば段階 1、そうでなければ水平に接する水の最小段階に 1 を足す。接する水がないか、計算結果が 8 以上なら空気に戻る。状態が変わった場合はその位置の処理を終える。
3. 広がる水は、まず真下の空気か段階付きの水を `falling` にする。真下に流れ込めない場合は、北・南・西・東の順に、空気か次の段階より浅い水を埋める。水源と `falling` からは段階 1、段階 n からは段階 n + 1 が広がる。段階 7 で横への広がりが止まる。

流れ込めるのは空気と規則に合う流れる水だけ。植物（花、短い草、小麦）、半ブロック、階段、柵、ガラスがあるマスには入らない。水がつながる境界では内部面を省き、高い水面と低い水面の間の側面だけを描く。真上に水がない場合、水源と `falling` の高さは従来と同じ 8/9 ブロック。段階 n の高さは `(16 - 2n) / 16` ブロック。真上に水があるマスの水は高さ 1 ブロックでつながる。上面と下面には `water`、側面には `water_flow` の既存の絵を使う。

泳ぎとサバイバルの移動検証の見直しは ⑥-3b で行う。

## バケツ

空のバケツは、水に当たる照準で最初に水源を狙って右クリックするとすくえる。水入りバケツは、通常の照準で狙った面の隣が空気か流れる水なら、右クリックで水源を置ける。水入りバケツで作業台やかまどを狙ったときは、Shift を押していなければ画面を開く。バケツ操作はサーバーからのブロック更新を待つ。

操作には手が届くこと、生存していること、画面を閉じていることが必要。サバイバルでは、手に 1 個あれば選択枠で空と水入りを交換する。空のバケツを重ねて持っていれば 1 個を消費し、水入りを所持品へ入れる。空きがなければ足元に落とす。クリエイティブでは手に持つバケツを消費・交換しない。

作業台に鉄インゴットを `["# #", " # "]` の形で 3 個並べると、空のバケツが 1 個できる。プロトコル 11 の C2S `UseBucket`（0x0f）は対象の x・y・z をそれぞれ i32 BE で送る。

## 確認

`tools/e2e.mjs` の `waterFlow()` はローカルのクリエイティブ Flat ワールド（シード 2026、表示距離 2、時刻 6000）で、ピッカーから水入りバケツと空のバケツを選ぶ。右クリックで水源の設置、周囲への広がり、水源の回収、周囲の排水を確認する。

⑥-3a の決定性シナリオ（シード 2026、600 tick）の指紋は、main の `d36da50f11b5eb81` から `ff3103752025dd92` に変わった。この台本では水は流れず、終了時の予定件数は 0。予定件数を状態ハッシュに加える分だけ指紋が変わることを、その項目を外した比較実行で確かめた。ブロック変更 2187 件、チャンク保存 24 件、再読み込み 16 件と、送信バイト列のハッシュは main と一致する。

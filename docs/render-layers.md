# 描画レイヤー・ブロック状態・部分形状（issue #16）

既存の状態 ID 0〜13（glass=11、oak_leaves=12、water=13）を保ち、
末尾にハーフブロックと草花の状態を追加した。
描画レイヤー、完全な遮蔽 `occludes`、衝突 `solid`、同種の面の省略 `cull_same`、
光の opacity / emission は独立した属性である。地形生成は変更しない。

Cube の面では、隣が occludes、または同じ状態 ID で cull_same のとき面を省略する。
Boxes は直方体の面がセル境界にある場合だけ同じ判定を使い、内部面は残す。
下付きハーフの上面、上付きハーフの下面は、隣が石でも消えない。
部分形状は occludes=false のため隣の面を隠さず、double のみ完全な遮蔽になる。
Cross は非表示判定をせず、×字2枚の表裏を4 quads として出力する。
これによりカットアウトの背面カリングを維持したまま、板の裏も描画できる。
ガラスと水は同種の内面を省き、葉は内面を残す。石の面は透明素材によって隠れない。
石に接するガラス側の面は隠れるため、石・ガラスが1個ずつ隣接する場合は石6面・ガラス5面。
石に完全に囲まれたガラスは0面になる。ガラスだけの例外は設けない。
AO と頂点周辺の光サンプリングの除外には occludes だけを使う。
セル境界の可視面では直外が必ず occludes=false なので、外側4セルの光採取は最低1サンプルを持つ。
内部面は AO=3（最大）とし、面の外側がある自セルの光をそのまま使う。
Cross も AO=3・自セルの光を使い、方向シェードは上面と同じ1.0とする。

頂点は2語のまま、位置と UV を1/16単位に変更した。ビットは下位から:

```text
word 0: x:9 | y:9 | z:9 | face:3 | ao:2
word 1: texture:12 | tint:1 | sky:4 | block:4 | u:5 | v:5 | water_top:1
```

位置はセクション内0〜256、UVは0〜16（復号時に16で割る）。
Boxes の各面は、箱のブロック内位置に対応した領域をテクスチャから切り取る。
例えば下付きハーフの側面はテクスチャ下半分になる。
4頂点（8語）を1 quad とし、
不透明→カットアウト→半透明の順に連結する。`mesh_section_layers` が3個の面数を返す。
WASM の `mesh_padded` / `client_mesh` は合計面数を返し、`client_mesh_ptr` が頂点先頭、
`client_mesh_count(0..2)` が直前の呼出しのレイヤー別面数を返す。空・無効入力では面数はすべて0。
Worker は頂点配列と面数を一緒に返す。メインのフォールバックも同じ ABI を使う。
共有インデックスは最大4096×6面を扱う。Cube と今回の1箱の Boxes は各セル最大6面、
両面の Cross は4面。密なハーフブロック・草花のセクションでもこの上限に収まる。
WGSL、`quadCenters`、半透明インデックスの並べ替えは同じ復号規則を使う。

描画順は空、不透明、カットアウトの後、カメラが雲面（Y=192）より下なら雲→半透明、
雲面と同じ高さか上なら半透明→雲とし、最後に選択枠を描く。
雲と半透明はどちらも深度を書かないため、水中から見上げる場合は雲を先に描き、
水面の色を通して雲が見えるようにする。雲面の高さは描画と順序判定で同じ定数を使う。
不透明とカットアウトは深度テスト・書込あり、カットアウトだけ alpha < 0.5 を discard。
半透明は深度テストあり・書込なしで、src-alpha / one-minus-src-alpha のブレンド。
不透明・カットアウトは背面をカリングする。半透明はカリングせず、水面を水中からも描く。
光マップ、方向シェード、AO、霧は3パスで共有する。
草は既存の色、葉と水はそれぞれ固定色をグレースケールのテクスチャに乗算する。
葉・水のテクスチャ番号は、GPU 配列への転送と同じテクスチャ名の配列から引いて
シェーダーに埋め込み、テクスチャの順序には依存しない。

半透明セクションは毎フレーム、セクション中心からカメラまでの距離の遠い順に描く。
quad 中心は4頂点の平均から求める。カメラのブロック座標が変わったときとメッシュ更新時に、
近い可視セクションから quad を遠い順に並べ直す。
処理開始から1 msで次のセクションへの着手を止める。1セクションのソート・GPU転送は
不可分なので、その1個の処理だけ予算を超える場合がある。未処理のセクションは次フレームに回す。
不可視だったセクションも再び見えた時点で必要なソートを行う。
頂点を動かさず半透明用のインデックスだけを更新するため、AO の対角線と UV を保てる。
距離の同値は元の順を保つ。交差する半透明面の厳密な合成や order-independent transparency は扱わない。

ガラス・葉・草花の mip は2×2平均の後、alpha >= 0.5 を満たすピクセルの割合を、
次の解像度で表現できる最も近い面積に合わせる。平均 alpha の高い順に選び、
通過する値は最低160、非通過は最大96とする。同値は決定論的な順序。
最小 mip では1ピクセル未満の面積を表現できないため丸めがある。
水と既存の不透明テクスチャには通常の RGBA 平均を使う。
全テクスチャは独自の手続き模様で、本家の画像は使用しない。

衝突は `solid` と `collision_boxes` を使い、1セルの複数の箱を列挙する。
クライアント予測とサーバー移動検証は共通の `physics::BlockWorld` を使う。
下付きハーフは高さ0.5、上付きは0.5〜1、double は1。段差0.6で下付きに上がれる。
水・草花は衝突せず、ガラス・葉は衝突する。未読込チャンクは移動上の壁になる。

レイキャストは `selection_boxes` に交差させ、空の半分を通り抜ける。
草花の選択箱は x/z=5/16〜11/16、y=0〜10/16。水は選択を通過する。
当たった面と自セル内の Y（0〜1、上端は1）、選択箱の min/max を返す。
WASM 出力は x/y/z/face と箱の min/max が十個の i32 LE、その後に Y が f64 LE。
選択枠はその箱を0.002ずつ膨らませる。選択箱は草花の板の全体とは一致しない。
水流・浮力・泳ぎ、階段・フェンス・隣との接続は扱わない。

Rust で面数、境界、AO・光採取、光の減衰、クライアントとサーバーの衝突・設置を検証。
`pnpm test:host` でセクション・quad の順序、レイヤー境界、WASM の面数とミップを検証する。
`tools/e2e.mjs` はガラスの奥・水の下の地形の素材を変更して画素が追従すること、
ガラスの透明部が地形の色を保つこと、水の色が描画されることとページエラーを確認する。
E2E はレビュー側で実行する。

決定論の既存台本は登録総数を乱数の範囲に使っていたため、そのままでは ID 追加だけで
編集対象と乱数列が変わる。`sim::scenario` の選択範囲を従来の air..=lamp_block に固定し、
seed=2026 / 600 ticks の既存ハッシュ `88d6e0e1abd58ec4` を Rust テストでも固定した。
新しい素材は別の素材・衝突・光・ABI テストで扱う。


## 状態とモデル

`BlockState` は保存・通信とも従来どおり u16。ブロックは連続した状態範囲を持ち、
先頭の状態がインベントリの既定値。`info(state)` は状態の描画・衝突・光情報を返す。
`block` / `properties` / `state_name` / `parse_state` でブロックと性質を相互変換する。

| ブロック | 状態 ID | モデル |
|---|---|---|
| 既存ブロック（air〜water） | 0〜13を維持 | Cube |
| oak_slab | 14 bottom、15 top、16 double | Boxes、Boxes、Cube |
| cobblestone_slab | 17 bottom、18 top、19 double | Boxes、Boxes、Cube |
| red_flower / yellow_flower / short_grass | 20 / 21 / 22 | Cross |

`Box16` の座標は0〜16。下付きは y=0〜8、上付きは8〜16。
ハーフは既存の板材・丸石テクスチャを使い、草花3種は独自の手続き生成カットアウト。
草はグレースケールに草色を乗算する。
`client_block_registry` は状態名、ブロック既定値・状態数、モデル、遮蔽、テクスチャ名を
JSON配列（添字が状態 ID）で返す。UI 側に状態 ID の対応表を重複して持たせない。
F3 の Target 行は `oak_slab[type=top]` のような状態文字列を表示する。

## 置き方とブロック一覧

クライアントの `placementState` はレイキャストの面と自セル内 Y を使う。
上面に置くハーフは bottom、下面なら top。側面は Y < 0.5 なら bottom、以上なら top。
同じブロックの下付きの上面、上付きの下面を狙えば、そのセルを double にする。
隣接する設置先も、同じ種類のハーフの空いた半分に対応する場合だけ double にできる。
それ以外の置き換え先は空気・水だけ。未読込や別種のハーフ、double、草花への上書きはしない。
草花・草は設置先の直下が `occludes=true` のときだけ置ける。下の支えが後から壊れても、
残った草花を除去する処理はない。体と重なる設置や、そこから抜ける既存の扱いは保つ。

E でブロック単位の一覧を開き、クリックで現在のホットバー枠を入れ替える。
E / Esc / 閉じるボタンで閉じる。開くと入力をクリアしてポインターロックを解除し、
閉じると再ロックを試みる。ブラウザーが拒否した場合は一時停止画面をクリックして再開できる。
E はキー設定でも予約し、古い保存設定に E の割当があれば既定設定に戻す。
中クリックは状態ではなくブロックの先頭状態を拾い、既存の枠を選ぶか現在の枠を入れ替える。
重複するホットバー枠は許可し、選択は状態 ID ではなく枠番号で管理する。

既定の9枠は stone / dirt / oak_planks / oak_slab / oak_log / glass / oak_leaves / water / lamp_block。
`cf-minecraft.hotbar.v1` に9個のブロック名を保存し、次回も先頭状態として復元する。
localStorage 自体へのアクセス・読書きは try/catch。壊れたデータ、不明な名前、空気、
枠数不正は既定に戻し、保存失敗時はそのセッション内で選択を維持する。

## サーバーの検証と決定論

サーバーは従来の参加・読込・範囲・距離検証に加えて、有効な状態 ID と、草花の直下の
`occludes` を検証する。置き換え制限はクライアント UI だけで行い、サーバーでは任意の
既存状態への上書きを許す。決定論の台本が同じセルを直接上書きする既存挙動を保つためである。
台本の地形生成・乱数の状態範囲は変更せず、native と Node の seed=2026 / 600 ticks は
`88d6e0e1abd58ec4` のまま。サーバーはハーフの向きを推測せず、受信した状態を適用する。

## 水面と本家との差

水セルの上が水でなければ、上面と側面の上端の頂点に `water_top` を付ける。
WGSL でその Y を1/9ブロック下げ、セル内8/9の高さにする。整数の1/16座標を丸めない。
上が水なら下げず、積み重なった水の側面は連続する。半透明の中心計算も同じ補正を使う。
これは源の水の高さだけを表し、流れによる高さ・隣接水からの勾配はない。

本家の方向別の光遮蔽や部分面の覆い合いは扱わない。上下のハーフ同士が接しても
相手の一部の面を切り取って隠す処理はなく、double のみ完全な遮蔽になる。
内部面・Cross の光は自セルの値、AO は最大とする簡略化である。
光の減衰の詳細は [lighting.md](lighting.md) を参照。

Rust は形状の座標・UV・面数・両面・水面、状態変換、段差・頭上の空間・草花通過、
サーバーとクライアントの経路、レイ交差・面・Y、設置の拒否と double を検証する。
host テストは置き方の境界、WASM レジストリ、ホットバー保存と破損、E の予約、
頂点復号・半透明の並べ替えを扱う。
E2E には下付きハーフの設置・歩いて上がる・double 化、草花の画素と通過、E/Esc、
一覧からの選択、再読込後の保存、中クリック、ページエラーの検査を含む。実行はレビュー側で行う。

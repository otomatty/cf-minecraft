# Mob と牛

サーバーが `BTreeMap<u32, Mob>` を持ち、ID 順に処理する。落ちているアイテムと同じ `next_entity_id` を使う。最初の種類は `MobKind::Cow = 0`。位置は足元の中心で、牛の当たり判定は幅 0.9 ブロック、高さ 1.3 ブロック。重力、衝突、小さな段差の上り方、ジャンプと遊泳にはプレイヤーと同じ物理を使う。歩行入力は `forward = 0.5` で、平地の定常速度は約 0.108 ブロック/tick（約 2.16 ブロック/秒）。

状態ハッシュには、牛がいるときに件数と、ID 順に種類、位置、速度、向き、年齢、接地・遊泳・ジャンプの状態、歩行目標と残り時間・連続停止回数を加える。⑦-2a では逃走目標・残り時間・連続停止回数と、落下開始高、溶岩・窒息の間隔カウンタも加える。牛が 0 頭のときは、牛の状態ハッシュには何も加えない。

## 歩き回り

- 止まっている牛は毎 tick、1/120 の確率で歩き始める。seed、牛の ID、`game_time` を整数ハッシュにかけ、用途別の値から方向と距離を選ぶ。乱数の内部状態は保存しない。
- 水平目標までの距離は最大 8 ブロック。歩きながら目標の方向へ向きを合わせる。yaw は度で 0 が +Z、90 が −X。
- 目標の 0.5 ブロック以内に入るか、100 tick 経過するか、ジャンプで上昇中の tick を除き、水平移動が 0.01 ブロック未満の tick が 2 回続いたときに止まる。
- 0.7 ブロック先の列を調べ、落差が 4 ブロック以上か、足元や体の進行先に溶岩があれば止まる。段差の上に空間があれば、物理の自動段差上りを超える 1 ブロックまでの段差でジャンプする。水の中ではジャンプ入力を入れて水面付近に浮く。

## 出現と消滅

- 400 tick（20 秒）ごとに、参加済みプレイヤーを ID 順に処理する。水平 64 ブロック以内に牛が 8 頭未満なら、プレイヤーの ID と時刻を使用した整数ハッシュで、水平 24〜48 ブロックの範囲から群れの中心の列を一度選ぶ。
- 中心の列はチャンクがメモリにあり、その列の最上部の固体が草ブロックで、直上 2 マスが空気で、ほかのプレイヤーから水平 24 ブロック以内に入らないことが条件。条件を満たせば、中心を含め 1〜3 頭を試みる。残りの候補は中心から水平 2 ブロック以内の異なる列を使い、同じ条件とプレイヤーからの距離を調べる。無効な列は飛ばす。8 頭の上限は出現を試すプレイヤーから水平 64 ブロック以内で判定する。別のプレイヤーの周りでは、この出現によって 8 頭を超えることもある。
- サバイバルとクリエイティブの両方で、昼夜や明るさに関係なく出現する。
- 参加済みのどのプレイヤーからも水平 128 ブロックより遠いか、チャンクがメモリにないか、足元が `health::VOID_Y`（−128）を下回る牛は消える。
- `Server::tick` のアイテム処理後に、出現、AI と物理、消滅の順で処理する。牛はワールドやチャンクの保存データに含めないため、ワールドを開き直した場合やチャンクが読み込み解除された場合は、その後の出現判定で新しい牛が現れる。

## 体力と攻撃

牛の体力は 10。参加済みで生存中のプレイヤーは、目（足元から 1.62 ブロック上）から牛の当たり判定（幅 0.9、高さ 1.3）の最も近い点まで 8 ブロック以内なら攻撃できる。サーバーは tick の先頭でパケットを受信順に処理する。

| 手に持っているもの | ダメージ |
| --- | --- |
| 素手、道具以外 | 1 |
| 斧 | tier + 2 |
| つるはし | tier + 1 |
| シャベル、鍬 | tier |

tier は `items.toml` の `tool.tier`（木 1、石 2、銅 3、鉄 4）。ダメージはゲームモード共通で、サバイバルではダメージが通るたびに疲労が 40 増える。

ダメージが入った tick に無敵時間は 10 tick になり、以後は tick の先頭で 1 ずつ減る。残り時間がある間はダメージとノックバックを受けない。残り 0 になった tick から攻撃が再び通る。サバイバルでは、Mob への打撃でダメージが入ったときや弓から矢を放ったとき、手に持った道具の [耐久値](items.md#耐久値) を 1 回分消費する。

ノックバックは攻撃者の足元から牛の足元へ向かう水平速度 0.4 で、元の水平速度を置き換える。水平位置が同じ場合は、サーバーが最後に受理した攻撃者の yaw の向きを使う。牛が接地していれば上向きの速度も 0.36 にする。牛は歩行をやめて `Wander::Idle` に戻り、無敵時間中は新しい歩行を始めない。（⑦-2a で変更。下の節を参照）

体力が 0 になると牛が消えてアイテムを落とす。牛がダメージを受けるのはプレイヤーの攻撃だけ。落下や溶岩では体力は減らない。（⑦-2a で変更。下の節を参照）

## 環境からのダメージ

- 毎 tick、移動後に落下、窒息、溶岩の順で判定する。牛の当たり判定で着地を検出し、落下の最高点から着地までの高低差を切り捨てて 3 を引く。結果が正ならその分だけダメージを受ける。足元が流体に入ると落下の記録を消す。
- 頭（足元から 1.1 ブロック上）が不透明な 1 マス全体のブロックに埋まると、10 tick ごとに窒息で 1 ダメージを受ける。足元から 0.4 ブロック上か頭に溶岩があると、10 tick ごとに 4 ダメージを受ける。
- 攻撃と環境ダメージは同じ 10 tick の無敵時間を使う。無敵中も落下の追跡と間隔の計測を続け、その間に発生したダメージは破棄する。環境ダメージにノックバックはない。
- 牛は溺れない。足元が奈落の消滅高度を下回ると、アイテムを落とさず消える。
- 溶岩で死亡したときは、精錬レシピのあるドロップをその出力（生の牛肉なら焼いた牛肉）に置き換える。個数の決め方は共通で、レシピのないアイテムはそのまま落ちる。
- 溶岩で死亡したときの落とし物は、足元から 0.4 ブロック上と頭の両方に溶岩がなかった最後の位置の、足元から 0.65 ブロック上に出る。この位置の初期値は出現位置。
- その位置を記録するのは、牛が接地していて、足元の中心の真下に落とし物を支える衝突形状を持つ、溶岩以外のブロックがあるときだけ。
- 溶岩の中にいる牛は、移動後の当たり判定が新しい溶岩セルに触れなければ移動できる。

## 逃げる

- ダメージを受けて生き残った牛は 60 tick 逃げる。再びダメージを受けると、残り時間を 60 tick に戻して目標を選び直す。
- 攻撃を受けると攻撃者から離れる水平方向を選ぶ。水平位置が同じ場合と環境ダメージの場合はランダムな方向を選ぶ。目標までの距離は 5〜8 ブロックで、0.01 ブロック刻み。
- 逃走の前進入力は `forward = 0.75`。段差でのジャンプや水中での動きは歩行と同じ。攻撃を受けた tick はノックバックを処理し、次の tick から逃走の前進入力を入れる。環境ダメージの場合も、逃走の前進入力は次の tick から入れる。
- 目標に着くか、崖や溶岩で進めないか、水平移動が 2 tick 続けて 0.01 ブロック未満になると、ランダムな目標を選び直す。停止回数にはジャンプで上昇中の tick を含めない。新しい目標への前進入力は次の tick から入れる。逃走時間が尽きると `Wander::Idle` に戻る。

## ルートテーブル

`data/registry/loot.toml` の `[[loot]]` に `mob`、`item`、`min`、`max` を指定する。未知の Mob 名やアイテム名、`min > max` はビルド時にエラーになる。

牛の項目は生の牛肉（`raw_beef`）1〜3 個。ワールドの seed、牛の ID、死亡時の `game_time`、項目番号を使った整数ハッシュから、両端を含む範囲内で個数を決める。個数が 0 の項目は出現しない。牛の中心（足元から 0.65 ブロック上）に、採掘のドロップと同じく拾得待ち 10 tick のアイテムを生成する。生の牛肉はかまどで焼いた牛肉（`cooked_beef`）になる。

## プロトコル13

複数バイトの値はビッグエンディアン。

| 方向 | 番号 | パケットと本体 |
| --- | --- | --- |
| S2C | 0x0d | `MobSpawn` — id u32、kind u8（牛は 0）、x/y/z f64、yaw f32 |
| S2C | 0x0e | `MobMove` — id u32、x/y/z f64、yaw f32 |
| S2C | 0x0a | `EntityRemove` — id u32。アイテムと共通 |

アイテムと同様に、クライアントへ送信済みの `sent` チャンクにいる牛だけを同期する。可視範囲に入ったら Spawn、位置または向きが変化したら Move、範囲から外れるか消滅したら Remove を送る。

## プロトコル14

| 方向 | 番号 | パケットと本体 |
| --- | --- | --- |
| C2S | 0x10 | `Attack` — id u32 |
| S2C | 0x0f | `MobHurt` — id u32 |

牛が攻撃を受けて生き残ったとき、すでにその牛の `MobSpawn` を受け取ったクライアントへ `MobHurt` を送る。死亡時は `EntityRemove` を送る。Wasm は牛ごとに最後の `MobHurt` の受信順を保持し、`window.__mc.stats().mobs` の `hurt` で読める。まだ攻撃を受けていない牛の値は 0。⑦-2a からは、環境のダメージを含め、最初の `MobHurt` を受け取るまで 0。⑦-2a からは、環境ダメージを受けて生き残ったときも同じクライアントへ `MobHurt` を送る。

## クライアントと E2E

Wasm は現在と前回の位置、ID、種類、向きを保持する。TS はアイテムと同様に 50 ms で位置を補間し、同じライトマップと霧を使う。牛、豚、鶏、羊のモデルとスキンは種類ごとに読み込み、同種の個体で共有する。歩行中は関節を支点に足を振る。モデルの座標系、スキンの UV、歩行時の角度は [モブの描画アセット](entities.md#モブの描画アセット) を参照。

`window.__mc.stats().mobs` で確認できる。`pnpm test:e2e` の `mobs()` はクリエイティブの Flat ワールド（seed 2026、view 4）を開き、最大 60 秒待って出現を確認する。同じ牛の移動と、ほかの牛が対象の近くやカメラとの間にいなくなるのを待つ。撮影時に対象の向きを確認し、スクリーンショットの鼻が映る範囲で色を調べる。

左クリックでは、カメラの視線と補間後の牛の当たり判定との交点を 5 ブロック以内で探す。最も近い牛がブロックより手前にいれば、牛を攻撃し、ブロックの枠線を隠す。左ボタンを押し続けると 250 ms ごとに攻撃する。サバイバルでは、採掘中に照準が牛に移ると採掘を中断する。牛を叩いた後は 250 ms が経過すると採掘を再開でき、ブロックを狙ってクリックし直した場合はすぐに採掘を始める。

`MobHurt` を受け取ってから 0.5 秒間、その牛を赤みがかった色で描く。

`mobCombat()` はサバイバルの Flat ワールド（seed 2026、view 4）で牛の出現を待ち、牛の近くから胴に照準を合わせてクリックする。最初の攻撃で `hurt` が増え、繰り返し攻撃すると同じ牛が消えることを確認する。奥にある草ブロックが残り、牛の近くに落ちた生の牛肉 1〜3 個を拾うとインベントリに入ることと、ページエラーがないことも確かめる。

## 決定性の確認

既存の seed 2026・600 tick の台本は `DebugHills`。600 tick を通して牛は 0 頭で、現行の指紋は `3452cbe46d067e47`。別途、テスト `herds_spawn_on_the_400th_tick_in_both_modes_and_repeat` では、Flat の seed 2026 でスポーン地点にプレイヤー ID 1 を表示距離 4 で参加させ、チャンクの要求を先に処理する。この条件で 400 tick に 3 頭が出現する。ID 順に足元座標は `(45.5, −60, 2.5)`、`(46.5, −60, 1.5)`、`(46.5, −60, 2.5)`。600 tick までに移動し、サバイバルとクリエイティブで同じ位置になることを確認する。

この 400 tick の群れは 3 頭とも牛。800 tick に同じ場所から出現を試すと豚が 1 頭出現する。

## 種類

種類ごとの値はサーバーの `MobSpec` で定義する。当たり判定の幅・高さはクライアントの照準にも使う。大きさの単位はブロックで、頭の高さは足元から測る。

| 種類 | 幅 | 高さ | 頭の高さ | 体力 | 歩行の前進入力 | 逃走の前進入力 | ドロップ |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 牛 | 0.9 | 1.3 | 1.1 | 10 | 0.5 | 0.75 | 生の牛肉 1〜3 個 |
| 豚 | 0.9 | 0.9 | 0.7 | 10 | 0.5 | 0.75 | 生の豚肉 1〜3 個 |
| 鶏 | 0.4 | 0.7 | 0.5 | 4 | 0.5 | 0.75 | 生の鶏肉 1 個、羽根 0〜2 個 |
| 羊 | 0.9 | 1.3 | 1.1 | 8 | 0.5 | 0.75 | 羊毛 1 個、生の羊肉 1〜2 個 |
| ゾンビ | 0.6 | 1.95 | 1.74 | 20 | 0.5 | — | 腐った肉 0〜2 個 |
| スケルトン | 0.6 | 1.99 | 1.74 | 20 | 0.5 | — | 骨 0〜2 個、矢 0〜2 個 |
| クリーパー | 0.6 | 1.7 | 1.45 | 20 | 0.5 | — | 火薬 0〜2 個 |

上の各節で「牛」と書いている移動、攻撃、環境ダメージ、逃走、出現・消滅、同期の規則は全種類で共通。窒息と溶岩は表の頭の高さで判定する。落とし物は当たり判定の高さの半分の位置に出る。生の豚肉（`raw_porkchop`）はかまどで焼いた豚肉（`cooked_porkchop`）になり、豚が溶岩で死んだ場合も焼いた豚肉を落とす。

種別は群れの中心と同じ seed、プレイヤー ID、`game_time` を使い、中心とは別の用途番号で整数ハッシュを計算して選ぶ。偶数なら牛、奇数なら豚で、各 1/2。群れの全個体は同じ種類になり、水平 64 ブロック以内の 8 頭の上限には両方を数える。

プロトコル 15 では `MobKind` に 1 = 豚を追加した。牛は 0 で、パケットの構造はプロトコル 14 と同じ。豚はピンクの胴と頭、突き出た鼻、短い脚 4 本を持ち、脚振り・赤い被弾表示・照明・霧には牛と同じ描画処理を使う。E2E の `mobs()` では豚の正面も撮影し、鼻のピンクの画素を確かめる。

鶏は空中で下向きの速度が最大 0.1 ブロック/tick で、落下ダメージを受けない。窒息と溶岩は共通の規則でダメージを受ける。溶岩で死ぬと焼いた鶏肉（`cooked_chicken`）を落とし、羽根はそのまま落とす。

出現時と産卵時に、seed、鶏の ID、その時の `game_time`、産卵用の用途番号を整数ハッシュにかけ、次の産卵までの間隔を 6000〜12000 tick（5〜10 分、両端を含む）から選ぶ。生きていて消滅しない鶏は、出現した tick を含め毎 tick `egg_ticks` を 1 減らす。0 になると足元に卵を 1 個落とし、採掘のドロップと同じく拾得待ちは 10 tick。状態ハッシュには鶏の `egg_ticks` も含める。

⑦-2c からは群れの種別ハッシュを 3 で割った余りで、牛・豚・鶏を各 1/3 で選ぶ。群れは全個体が同じ種類で、近くの上限には 3 種類すべてを数える。「決定性の確認」と同じ Flat の seed 2026、プレイヤー ID 1、スポーン地点、表示距離 4 の条件では、400 tick に牛 3 頭、800 tick に豚 1 頭が出現する。上限に空きがあれば、2000 tick と 2400 tick は鶏の群れを選ぶ。

プロトコル 16 では `MobKind` に 2 = 鶏を追加した。`MobSpawn` などのパケット構造は共通。鶏は白い羽、オレンジのくちばし、赤い肉垂れ、黄色い脚を持ち、歩くと 2 本の脚を振る。E2E の `mobs()` では鶏の正面も撮影し、くちばしのオレンジの画素を確かめる。

羊の当たり判定は幅 0.9、高さ 1.3、頭の高さは足元から 1.1。体力は 8。歩行の前進入力は 0.5、逃走の前進入力は 0.75。落ちる速さの上限はなく、落下ダメージを受ける。ドロップは羊毛（`white_wool`）1 個と生の羊肉（`raw_mutton`）1〜2 個。溶岩で死ぬと羊肉は焼いた羊肉（`cooked_mutton`）になり、羊毛は精錬レシピがないのでそのまま残る。

⑦-2d からは群れの種別ハッシュを 4 で割った余りで、牛・豚・鶏・羊を各 1/4 で選ぶ。群れは全個体が同じ種類で、近くの上限には 4 種類すべてを数える。「決定性の確認」と同じ Flat の seed 2026、プレイヤー ID 1、スポーン地点、表示距離 4 の条件では、400 tick に鶏 3 頭、800 tick に羊 1 頭、1200 tick に牛 2 頭が出現する。上限に空きがあれば、2000 tick は豚 1 頭を選ぶ。2400 tick は鶏 2 頭、2800 tick は羊 1 頭、3600 tick は豚 1 頭、5200 tick は羊 2 頭。

プロトコル 17 では `MobKind` に 3 = 羊を追加した。`MobSpawn` などのパケット構造は共通。羊は牛より少し丸く大きい白い毛の胴（毛の箱を胴のまわりに重ねたもの）、毛より暗い顔、下が暗い色の脚 4 本を持ち、歩くと脚を振る。E2E の `mobs()` では羊の正面も撮影し、白い毛の画素を確かめる。

## ゾンビ(⑦-3a)

- `day_time` を 24000 で割った余りが 13000 以上 23000 未満なら夜、12000 未満なら昼。残りは夕方と明け方。
- 夜は 200 tick ごとに、ゲームモードを問わず参加済みのプレイヤーを ID 順に処理する。水平 64 ブロック以内のゾンビが 4 体未満なら、seed、プレイヤー ID、`game_time`、ゾンビ出現用の用途番号を使った整数ハッシュで水平 24〜48 ブロックの列を 1 つ選ぶ。動物の群れは従来の 400 tick 周期で、上限 8 頭には動物だけを数える。
- 出現する列のチャンクはメモリ上にあり、最上部の固体は 1 マス全体の衝突形状を持ち、葉・水・溶岩以外で、すぐ上の 2 マスが空気であること。その固体から世界の最上部までの同じ列に水も溶岩もないこと。ほかの参加済みプレイヤーから水平 24 ブロック以内にある列では出現しない。光量の判定は行わない。消滅は動物と同じ。
- 毎 tick、足元どうしの 3 次元距離が 16 ブロック以内で最も近い生存中のサバイバルプレイヤーを選ぶ。同距離なら小さい ID を優先する。対象へ向いて前進入力 0.6 で追い、段差でのジャンプ、水中で浮く動き、溶岩や 4 ブロック以上の落差を避ける規則は歩行と共通。対象がいなくなると歩き回りに戻る。
- 攻撃の待ち時間は毎 tick の先頭で 1 減る。移動後、待ち時間が 0 で、対象とゾンビの当たり判定の最短距離が 0.8 ブロック以下なら、対象に 3 ダメージを与えて待ち時間を 20 tick にする。
- ゾンビは攻撃を受けたときのノックバックを受ける。被弾時と環境ダメージ時の逃走は動物に適用する。ゾンビは落下ダメージを受け、落下速度に上限がない。
- 昼の間、水の中におらず、頭のブロックより上の同じ列に衝突形状も水もなく、頭と同じセルに下端が頭の高さ以上の衝突箱もなければ、連続して条件を満たす 20 tick ごとに 2 の日光ダメージを受ける。無敵時間と赤い被弾表示はほかのダメージと共通。死亡時は腐った肉（`rotten_flesh`）を 0〜2 個落とす。溶岩で死んだ場合も腐った肉を落とす。腐った肉は満腹度を 4 回復する。
- ゾンビの攻撃待ち時間と日光の間隔カウンタは、ID 順の Mob 状態ハッシュで該当個体の末尾に加える。追跡対象は tick ごとに選び直す。

## プロトコル 18

`MobKind` に 4 = ゾンビ、`DeathCause` に 6 = ゾンビの攻撃を追加した。パケットの構造は従来と共通。クライアントは既存のゾンビのモデルと 64×32 のスキンを使い、脚振り、被弾表示、照明、霧は共通の処理で描画する。`window.__mc.stats().mobs` には kind 4 で表示される。E2E の `zombies()` は夜の Flat サバイバルで出現、追跡、プレイヤーへのダメージを確認し、撮影したゾンビの緑の肌の画素を調べる。

## スケルトンと矢(⑦-3b)

- 夜の出現判定では、列を決めるハッシュとは別に seed、プレイヤー ID、`game_time`、用途番号 24 で整数ハッシュを計算する。偶数ならゾンビ、奇数ならスケルトン。水平 64 ブロック以内の上限 4 体には両方を数える。200 tick 周期、空の見える出現列、消滅条件は共通。動物の出現判定は従来どおり。
- 日光と被弾時の規則はゾンビと共通。スケルトンは落下ダメージを受け、倒れると骨と矢をそれぞれ 0〜2 個落とす。
- サバイバルの参加済みで生存中のプレイヤーから、16 ブロック以内で最も近い者を毎 tick 選ぶ。目から目までの線分にブロックの衝突形状がなく、水平距離が 10 ブロック以下ならその場で相手を向く。それ以外は前進入力 0.6 で追跡する。
- 近接攻撃は行わない。射撃の待ち時間は出現時に 20 tick で、毎 tick の先頭で 1 減る。残り 0 で 16 ブロック以内の対象に視線が通れば、目の位置から矢を 1 本放ち、待ち時間を 40 tick にする。狙いは対象の目を水平距離 × 0.08 ブロック分上にずらした点で、初速は 1.2 ブロック/tick。待ち時間はスケルトンの状態ハッシュに加える。
- 矢の移動、衝突と寿命は [エンティティ](entities.md#スケルトンの矢⑦-3b) を参照。

## プロトコル 19

`MobKind` に 5 = スケルトン、`DeathCause` に 7 = 矢の攻撃を追加した。`ArrowSpawn`（`0x10`）と `ArrowMove`（`0x11`）はエンティティ ID と位置・速度を同期し、消滅には `EntityRemove` を使う。クライアントは既存の 64×32 スキンと右手の弓の絵を使い、矢を描画する。`window.__mc.stats().arrows` には ID、位置、速度を出す。E2E の `skeletons()` は夜の Flat サバイバル（seed 2027）で出現、飛翔中の矢、プレイヤーの被弾、撮影した骨の画素を確認する。

## クリーパーと爆発(⑦-3c)

- 夜の出現では、用途番号 24 の整数ハッシュを 3 で割った余りで種類を選ぶ。0 がゾンビ、1 がスケルトン、2 がクリーパーで、各 1/3。水平 64 ブロック以内の上限 4 体には 3 種類を合わせて数える。200 tick 周期、空の見える出現列、消滅条件はゾンビ・スケルトンと共通。動物の出現判定と結果は変えない。
- クリーパーは日光では燃えない。近接攻撃も射撃もしない。追跡の対象と前進入力 0.6 はゾンビと共通。倒されると火薬（`gunpowder`）を 0〜2 個落とす。
- 点火の時間 `fuse`（tick）を持つ。毎 tick、対象がいて足元どうしの 3 次元距離が 3 ブロック以内かつ目から目までの視線が通っていれば `fuse` を 1 増やし、その tick は止まって対象を向く。そうでなく `fuse` が 0 より大きければ 1 減らす。この間は対象がいれば追う。
- `fuse` が 30 に達した tick に爆発し、クリーパーは消える。爆発では火薬を落とさず、死因も扱わない。中心は足元から 0.85 上。
- 中心からブロック中心までの距離が 3.0 以下のブロックを、空気・流体・`unbreakable`・`dig_ticks` が 250 以上のものを除いて空気にする。順番は y、z、x の昇順。壊したブロックは seed、`game_time`、位置、用途番号 25 の整数ハッシュで 1/3 の確率で、道具の条件なしの通常の落とし物を落とす。かまどの中身、掘っている途中の取り消し、ブロックの送信、流体の近くの更新、小麦の確認はプレイヤーが掘ったときと同じ。
- 生存中のサバイバルのプレイヤーには、中心から体の中心（足元から 0.9 上）までの距離 d が 6 未満のとき `floor(15 × (6 − d) / 6)` のダメージを与える。0 なら何もしない。死因は `DeathCause::Explosion`。壁による減衰とノックバックはしない。
- ほかの Mob には同じ式で、当たり判定の中心（足元から高さの半分）までの距離で、既存の被弾処理を通してダメージを与える。落ちているアイテムと矢には影響しない。
- ⑦-3f で露出率によるダメージの減衰、プレイヤーの押し飛ばし、落ちているアイテムの消滅を追加した。[爆発の仕上げ(⑦-3f)](#爆発の仕上げ⑦-3f) を参照。
- クリーパーの `fuse` は、クリーパーがいるときだけ既存の敵の状態ハッシュの末尾に加える。

## プロトコル 20

`PROTOCOL_VERSION` は 20。`MobKind` に 6 = クリーパー、`DeathCause` に 8 = 爆発を追加した。`MobFuse`（`0x12`）はエンティティ ID と `fuse`（0〜30）を送り、値が変わった tick と、点火中のクリーパーを新たに視界に入れたときの `MobSpawn` の直後に送る。クライアントは既存の 64×32 のクリーパーのスキンを使い、`fuse` が 4 tick ごとに白く点滅し、30 で 1.2 倍まで膨らむ。`window.__mc.stats().mobs` には `fuse` を出す。E2E の `creepers()` は夜の Flat サバイバルで出現、点火、爆発による消滅と体力の減少、地面のブロックが空気になることを確認し、撮影した緑の画素を調べる。

## 弓とプレイヤーの矢(⑦-3d)

- 弓を持って右クリックを押すと、サバイバルでは所持品に矢があるとき、クリエイティブでは矢の有無にかかわらず引き始める。引きは毎 tick 進み、上限は 20 tick。離したときに 3 tick 以上なら発射する。枠や手に持つものが変わったとき、画面を開いたとき、死亡したときは発射せずに中断する。
- 発射時の力は `power = draw / 20`、初速は `0.6 + 2.4 × power` ブロック/tick。サーバーが最後に受理した視線を使い、足元から 1.62 ブロック上の目を起点に、視線方向へ 0.3 ブロック進んだ位置から放つ。サバイバルではホットバー、残りの所持品の順に先頭から矢を探して 1 本消費し、疲労を 50 加える。
- プレイヤーの矢は移動線分が最初に交差する Mob に `1 + floor(power × 8)` のダメージを与えて消える。既存の無敵時間、赤い表示、ノックバック、動物の逃走、死亡とドロップを適用し、水平ノックバックは矢の進行方向を使う。壁が先または同時なら矢は刺さる。スケルトンの矢は従来どおりプレイヤーに当たり、プレイヤーの矢の対象は Mob に限る。飛翔中の減速、重力、寿命は共通。
- サバイバルで撃った矢は、刺さって 10 tick 後から、参加済みで生存中のサバイバルプレイヤーが矢の位置に水平・垂直それぞれ当たり判定から 1 ブロック以内まで近づくと拾える。複数人が近いときは ID 順に、所持品に入る最初のプレイヤーに 1 本加える。スケルトンとクリエイティブの矢は拾えない。刺さった矢の消滅には既存の寿命を使う。
- 矢が存在する間は撃った者と力を状態ハッシュに含める。プロトコル 21 では、中断用の `CancelUsingItem`（C2S の `0x11`、ペイロードなし）を追加する。発射と拾得の結果は既存の矢と所持品のパケットで同期する。
- クライアントは引きに応じて視野角を最大 10% 狭め、`window.__mc.stats().bowDraw` にローカルの引きの tick 数を出す。E2E の `bow()` は昼の Flat クリエイティブで、最大まで引いたときの速さと狙った牛への被弾を確かめる。

加えて、足元の空気セルのブロックライトが0であることを要求する。たいまつや

## 暗い場所への敵の出現(⑦-4c)

昼夜を問わず 200 tick ごとに、ゲームモードを問わず参加済みのプレイヤーを ID 順に処理し、1 人につき候補を 1 列だけ試す。`tick_mobs` では動物の群れ（400 tick）のあと、夜の地上の敵（`day_time` を 24000 で割った余りが 13000 以上 23000 未満のとき、同じ 200 tick）を試し、その次にこの判定を行う。夜の同じ tick では地上の候補が先に 4 体の枠を使う。

列は地上の夜と同じ水平 24〜48 ブロックの輪から選ぶ。seed、プレイヤー ID、`game_time`、用途番号 26 の整数ハッシュを使う。高さの起点は、プレイヤーの足元の Y を切り捨てた値に −16 以上 16 以下（`(roll >> 32) % 33 - 16`、33 通り）を足した位置。そこから下へ、起点を含めて最大 16 マスを順に見る。葉・水・溶岩を除き、1 マス全体の衝突形状を持つ固体で、その直上が空気 2 マスのとき、下側の空気セルを足元にする。建築上限より上のマスは飛ばし、下限を下回ったら打ち切る。

足元の空気セルは、スカイライトとブロックライトがどちらも 0 であること。サーバーのチャンク照明は無効のまま、[局所スカイライト](lighting.md#サーバーでの局所的なスカイライト⑦-4c)と[局所ブロックライト](lighting.md#サーバーでの局所的なブロックライト⑦-4a)で求める。ほかの参加済みプレイヤーから水平 24 ブロック以内の列では出現しない。そのプレイヤーから水平 64 ブロック以内の敵が 4 体いるときも出現しない。この 4 体にはゾンビ・スケルトン・クリーパーを地上の夜と合わせて数え、動物は数えない。

種類は用途番号 27 の整数ハッシュを 3 で割った余りで、0 がゾンビ、1 がスケルトン、2 がクリーパー。各 1/3。地上の用途番号 24 とは別の抽選。消滅、追跡、攻撃は従来どおり。整数の tick とハッシュだけで決め、`HashMap` は使わない。プロトコルと保存形式は変えない。

seed 2026・600 tick の決定論台本の指紋は、この変更時点では `7c46257055d8c652` のままだった。この台本では暗い場所の敵は出現しない。

## 押し返しと燃えている見た目(⑦-3e)

- ゾンビの近接攻撃で対象が生存した場合、サーバーはそのプレイヤーだけに押し返しを送る。水平成分はゾンビの足元からプレイヤーの足元へ向かう単位ベクトルに 0.4 ブロック/tick を掛け、上向きの成分は 0.36 ブロック/tick。水平座標が一致した場合は上向きの成分だけを送る。
- WASM クライアントは受信した値を予測中の速度に加え、通常のプレイヤー物理で衝突と着地を処理する。サーバーの速度・衝突・サバイバル移動の検証は従来どおり適用する。被弾時の画面効果は体力更新に合わせて表示する。
- サーバーは毎 tick、Mob が日光にさらされているゾンビ・スケルトンか、頭または足元で溶岩に触れているかを調べる。日光には既存の日光ダメージの露出判定を使い、空から覆われている場合や水中では日光で燃えない。サーバーは燃焼状態が変わったときにその Mob を見ているクライアントへ送り、燃焼中の Mob を新たに送るときは `MobSpawn` の直後に `true` を送る。燃焼状態は毎 tick 求める描画用の値で、保存と状態ハッシュの対象外。
- クライアントは Mob の当たり判定に合わせた 2 枚の交差する板に、たいまつと同系色の 16×16 画素の切り抜き絵を 3 コマで描く。炎の色には照明による減光を適用せず、霧と遮蔽はほかの描画と共通。デバッグ表示では `stats().mobs` に `burning`、`stats()` に最後に受け取った押し返しの速度・位置・受信時刻・位置補正回数を `lastKnockback` として出す。
- E2E の `zombies()` は夜の Flat サバイバルで被弾後に水平 0.3 ブロック以上押し返され、`PlayerCorrect` が届かないことを確かめる。`mobBurning()` は Flat クリエイティブで夜に出現を待ち、開発用のローカル時刻設定で正午に進める。同じ Mob の `burning` が `true` になり、スクリーンショットの Mob 付近に橙色や黄色の画素が現れ、屋根で日光を遮ると `false` に戻ることを確かめる。

### 押し返しの合成の修正

上記の単純加算は飛行中に適用する。歩行時はパケットを受け取るたびに、水平方向を `vx = vx / 2 + kx`、`vz = vz / 2 + kz` で合成する。流体に触れず接地しているときだけ、鉛直方向を `vy = min(0.4, vy / 2 + ky)` で合成する。ジャンプ中・落下中や水・溶岩の中では鉛直速度を維持する。単位はブロック/tick。

同じ tick や連続する tick に押し返しが届いても、押し返しによる上昇の初速は最大 0.4 に収まる。通常のジャンプの初速は 0.42。パケットの形式と送信値、サーバーの上昇上限・空中の猶予・水平の移動予算は従来どおり。Rust の軌道テストでは、平地・壁際・ジャンプ中・連続被弾から補正なしで着地できることと、押し返しがないときの上昇上限を超えた移動が補正されることを確かめる。

## 爆発の仕上げ(⑦-3f)

### 露出率とダメージ

爆心はクリーパーの当たり判定の中央。対象の当たり判定を各軸の両端と中央で区切った 3 × 3 × 3 の 27 点から爆心へ線分を伸ばし、通った本数を 27 で割って露出率を求める。遮るのは衝突形状が 1 マス全体を占める固体で、面に触れるだけなら通る。空気・流体・部分形状は通り、未読み込みのチャンクを通る線分は遮られる。その爆発でブロックを破壊する前の世界を使う。

線分が整数座標の面に沿うとき、その面の両側が完全な立方体で埋まっている区間は遮られる。片側が空いていれば通る。2 軸の整数座標が交わる辺に沿うときは、その辺を囲む 4 セルがすべて完全な立方体で埋まっている区間で遮られる。

サバイバルの生存プレイヤーと生存中の Mob は、胴体の中心から爆心までの距離を `d` ブロックとして、`floor(15 × (1 − d / 6) × 露出率)` のダメージを受ける。距離が 6 ブロック以上か露出率が 0 のときは 0。Mob の既存の無敵時間は引き続き適用する。

### 処理の順番と押し飛ばし

1. 同じ tick に起爆するクリーパーの爆心を確定して本体を取り除く。各爆心について順に `Explosion` を通知する。
2. プレイヤーのダメージと押し飛ばしを処理し、次に Mob のダメージ・死亡・戦利品を処理する。
3. 爆発の処理を始めた時点で存在した落ちているアイテムの ID を候補とする。当たり判定の中心が爆心から 6 ブロック未満で露出率が 0 より大きければ消滅する。同じ爆発で倒した Mob の戦利品は残る。矢はこの判定の対象外。
4. 爆心から中心が 3 ブロック以内の破壊可能なブロックを壊す。ブロック破壊で生じるアイテムも、その爆発では残る。プレイヤーの死亡の確定処理は同じ tick の爆発を処理した後に行う。

範囲内で露出率が正のサバイバルプレイヤーが生存したら、サーバーは本人に `PlayerKnockback` を送る。`impact = (1 − d / 6) × 露出率` とし、爆心からプレイヤーの胴体の中心に向かう単位ベクトルの水平成分に `1.0 × impact`、鉛直成分に `0.5 × impact` を掛ける。距離が 0 のときは上向きに `0.5 × impact`。単位はブロック/tick。ダメージの端数切り捨てで 0 になっても押し飛ばしは届く。

クライアントは既存の押し返しと同じ合成を使う。歩行時は現在の水平速度を半分にしてから受信した水平速度を足す。流体に触れず接地しているときは `vy = min(0.4, vy / 2 + ky)` で鉛直速度を合成し、空中や流体内では鉛直速度を維持する。飛行時は受信した速度を加算する。

### 煙の描画と E2E

クライアントは爆心の周りに白から黄色の爆風を 5 粒出し、少し遅れて灰色の煙を 16 粒出す。新しい 16×16 画素の切り抜き絵（爆風 2 コマ、煙 4 コマ）を、カメラを向く板に炎と同じ減光なしのパスで描く。煙は外側へ広がりながら上昇して縮み、約 1〜1.5 秒で消える。待機中も含めて最大 256 粒に収める。時刻と乱数は描画にだけ使う。爆発音は従来どおりクリーパーの消滅から鳴らす。

`window.__mc.stats()` は受信回数を `explosionsReceived`、最後の爆心を `lastExplosionCenter`、描画中の粒数を `explosionParticles` に出す。`lastExplosion` は爆心、受信時刻、パケットの受信順を示す通し番号 `seq` を持つ。`lastKnockback` にも同じ通し番号を出す。

E2E の `creepers()` は夜の Flat サバイバルで爆発を受信し、直後のゲーム画面の爆心付近に灰色の煙の画素があることを確かめる。撮影した爆発の次に受け取ったパケットが押し飛ばしであることを通し番号で確認する。体力の減少と地面の破壊に加え、その押し飛ばしでプレイヤーが水平に 0.3 ブロック以上爆心から離れる向きへ動き、その間と直後に位置補正が起きず、ページエラーもないことを確かめる。遮蔽物による減衰と落ちているアイテムの消滅は Rust のテストで確認する。
点火確認時点で押し返しの累計 `knockbacksReceived` が 0 件であることと、点火確認から変位の測定までに届く押し返しが撮影した爆発の 1 件だけであることを確かめる。

# 公式テクスチャのインストール

1. タイトル画面で Google アカウントにログインします。シングルプレイにもログインが必要です。開発モード（`DEBUG=1`）ではログインを省略できます。
2. 「テクスチャをインストール」で公式のリリースページを開き、最新版の Assets にある、名前が `-full.zip` で終わるファイルを保存します。ダウンロードすると Minecraft の使用許諾契約（EULA）に同意したことになります。[Bedrock Samples の最新版](https://github.com/Mojang/bedrock-samples/releases/latest)
3. 保存した ZIP をタイトル画面にドロップするか、「ファイルを選ぶ」から開きます。保存が終わるとメニューが表示され、背景にもテクスチャが適用されます。[タイトル背景の描画](title-background.md)

タイトル画面の「入れ直す」、またはプレイ中の「設定」→「テクスチャ」→「別の ZIP に入れ替える」から更新できます。失敗したときは、それまでのパックを使い続けます。

使用する画像・モデルとパックのバージョンは、このサイトの IndexedDB に保存します。テクスチャの保存にはサイトデータの保存権限が必要です。パックのデータはブラウザ内で処理し、外部に送信しません。サイトデータを消すと、次に遊ぶときにインストール画面が出ます。以前の形式で保存したパックも、最新版の手順でインストールし直してください。

## 対応する ZIP

- ZIP の直下、または直下の1つのフォルダーに `resource_pack/` が必要です。`manifest.json` の `header` には Bedrock Samples の UUID と、非負の整数3個の `min_engine_version` が必要です。`bedrock-samples-v…-full.zip` の版の先頭3要素が一致すればファイル名の版を表示し、プレビューの接尾辞も引き継ぎます。それ以外では `min_engine_version` を表示します。
- `resource_pack/textures/` の `terrain_texture.json` と `item_texture.json` を使い、ゲームに対応するブロック面とアイテムの画像を取り出します。画像を取得するには `-full.zip` を選びます。
- チェストのブロック面は `chest_inventory` の0番目（`chest_top`）、1番目（`chest_side`）、2番目（`chest_front`）を使います。アイテムのアイコンもブロックの面から描画します。
- PNG を優先し、同じパスに PNG がなければカラーマップなしの32ビット TGA（非圧縮・RLE）を使います。ブロックとアイテムは画像の先頭の正方形を最近傍で 16 × 16 に変換します。水の縦並び画像は最大32コマを取り込み、元のコマ数に応じて繰り返します。草の側面はパックの土と草の重ね画像を合成し、バイオームの草色を使います。

- エンティティのクライアント定義から画像のパスとモデルの識別子を取得する。スキンは元の寸法で保存する。モデルは `models/` の旧形式（継承を含む）と現行の `minecraft:geometry` の形式に対応する。[モブの描画アセット](entities.md#モブの描画アセット)
- 燃えているときの炎は `textures/blocks/fire_0` の縦並びのコマを使う。爆発と煙のコマは、パーティクル定義の画像パスと UV を使って切り出す。

ZIP は 256 MiB、32,768 項目、宣言された展開サイズの合計は 512 MiB までです。使用する JSON は各 2 MiB、画像は各 4 MiB までで、読み込む画像とエンティティ・モデル・パーティクルの定義は合計 32 MiB までです。画像の幅は 512 ピクセル、高さは 4,096 ピクセル、面積は 1,048,576 ピクセルまでです。読み出すファイルには無圧縮または Deflate 形式を使用します。

## ベッドのテクスチャ

Bedrock Samples の terrain atlas にはベッドの六つの面に対応するタイルがないため、`bed.entity.json` が参照する `resource_pack/textures/entity/bed/white.png` を読み込み時に切り出します。面別の画像がパックにあれば、その面には通常のブロック画像を優先します。底面はオークの板を使います。インストール済みのパックにベッドの面が含まれていない場合は、ZIP を入れ直すと切り出した面が使われます。[terrain atlas](https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/textures/terrain_texture.json)・[ベッドの定義](https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/entity/bed.entity.json)・[白いベッドの展開図](https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/textures/entity/bed/white.png)

`models/mobs.json` の `geometry.bed` では、64 × 64 の展開図に対し、マットレスの箱は 16 × 32 × 6、box UV は `[0, 0]` です。箱の UV から次の領域を使います。座標は左上からのピクセル数です。[Bedrock Samples のモデル定義](https://github.com/Mojang/bedrock-samples/blob/main/resource_pack/models/mobs.json#L1117-L1199)

| 面 | 頭の領域 (x, y, 幅, 高さ) | 足の領域 (x, y, 幅, 高さ) |
| --- | --- | --- |
| 上 | (6, 6, 16, 16) | (6, 22, 16, 16) |
| 長い側面 | (0, 6, 6, 16) | (0, 22, 6, 16) |
| 端 | (6, 0, 16, 6) | (22, 0, 16, 6) |

長い側面は 90° 回し、端は上下を返して木枠を下に置きます。側面と端は 6 行を最近傍で 9 行に伸ばし、高さ 9/16 の面で使うタイルの下 9 行に入れます。残りの行には上端の色を繰り返し、遠くから描画したときに黒が混ざるのを防ぎます。

## 画像が見つからない場合

ゲームが使うブロックまたはアイテムの画像を1枚以上取り出せた場合は、残りの画像が欠けていてもインストールしてプレイできます。画像を収録していない `-min.zip` など、該当する画像を1枚も取り出せない ZIP はインストールできません。公式のリリースページで `-full.zip` を選び直してください。

タイトルのメニューと設定の「テクスチャ」に、見つからなかった画像の件数が表示されます。件数にはゲームが参照するブロック面・アイテム・ひび・空・HUD の画像キーと、各エンティティ・炎・爆発の解決結果を含みます。ブロックとアイテムの欠けは紫と黒の市松模様、HUD アイコンの欠けは単色の四角で表示します。採掘のひび、太陽・月・雲は、対応する画像がある場合に描画します。

エンティティの画像かモデルが欠けた場合は、当たり判定に合わせた市松模様の箱を表示します。羊の通常と毛刈り後の姿は、どちらかが欠けると合わせて 1 件に数えます。炎の画像が欠けた場合は炎を省略します。爆発や煙の画像が欠けた場合は、該当する粒子を広がる単色の四角で表示します。

## 開発と検証

リポジトリのルートで WASM をビルドし、仮パックを書き出します。仮パックはレジストリの名前から生成した画像と、テスト専用の独自スキン・モデル・エフェクトを使います。ブロックやアイテムを追加するときは、公式パックの画像への対応付けを取り込み処理に足し、仮パックにも対応する画像を用意します。[取り込み処理](../apps/web/src/client/texture-pack.ts)・[仮パック](../apps/web/test/texture-pack-fixture.mjs)

```sh
pnpm build:wasm
node tools/fixture-pack.mjs /tmp/fixture-full.zip
pnpm --filter web dev
```

タイトル画面で生成した ZIP を選ぶと、開発モードでプレイできます。E2E もタイトル画面から仮パックをインストールします。

WASM のビルド後、手元の公式 ZIP でゲームが使う画像とエンティティの形がすべて解決できるか確認できます。

```sh
node tools/check-official-pack.mjs /path/to/bedrock-samples-v1.26.60.5-full.zip
```

取り込めるパックは版、解決件数、未解決の名前を表示します。取り込みに失敗した場合や未解決の名前がある場合は終了コード 1 を返します。PNG は取り込み時の構造検査まで行い、TGA は実際にデコードします。公式 ZIP はローカルで指定し、この検査は CI では実行しません。
